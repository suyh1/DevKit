# 45 个工具的交互逻辑审查 · v1.9.2

审查以“输入是否被无意修改、按钮是否兑现名称、复制是否对应所见值、结果是否过期、后续工具能否直接使用”为准。拆分和填入保留输入原文，改变表示由用户主动转换；计算得到的新数据保留精度。保留旧源码供对照，禁止将失效结果当成当前结果复制、导出或发送。

## 确认并修复的问题

1. 坐标对填入曾将 DMS 自动改为十进制度。现在拆分后保留单个角度原文，包括方向、全角数字、单位和尾零，并按标识放入正确字段；圆心页同样处理。无效坐标不会部分写入。
2. 提取点或转换点用作圆心曾只传数值。现在保留原始角度；圆周计算出的新点才以完整浮点数传递。两种圆周算法仍接受完整小数和科学计数法。
3. 同一经纬值显示两种格式，单值复制却由公共设置决定。现在每种表示有自己的复制按钮，复制的就是旁边的值；整列/坐标对仍按公共设置。
4. 失效、失败、取消或恢复的文本结果曾能复制、导出、发送。现在这些操作禁用，成功后恢复；成功的空结果明确显示，并可复制/导出。
5. ULID 切换模式曾把用户内容覆盖为示例/数量。现在分别保留生成数量和解析草稿；首次切换可使用刚生成的真实标识，示例只由示例按钮填入。
6. HTTP 表单修改 URL 曾将整个 JSON 重新序列化，可能改写 body 中的大整数。现在仅替换指定值，预览保留原文；Fetch/Axios/cURL 保留结构化 body 数字原文。缺失的 JSON Content-Type 自动补齐，用户指定值优先。
7. JWT 解码及专属预览曾重新序列化大整数。现在 Header/Payload 保留 JSON 数字原文，结构节点复制也使用原文；拒绝含歧义的重复声明。
8. Java 结果送类型解析未衔接 Java，TSV 未提供对应 CSV 解析入口，同一编解码工具接收结果未衔接反方向。现在保持结果文本原样，自动选已知语言、分隔符或方向，用户仍可调整。
9. 差异工具交换两份文本缺少撤销；“下一处差异”第一次会跳过首块。现在可撤销交换，首次跳转到首块；重新计算重置导航。
10. Query/.env/Properties 的 JSON 编码输入曾静默覆盖重复键。现在报错并保留输入，请先消除歧义。HTTP 配置和 headers 顶层重复键同样拒绝。
11. 异步粘贴/导入与快捷键执行可能交错；现在新输入到达时停止旧 Worker，避免旧输入的结果覆盖当前输入。可选目标随结果类型变化时，实际发送目标与当前显示的选项保持一致。
12. 坐标格式转换在两个字段为空时曾尝试读取文本提取页的隐藏输入；现在只读取当前经纬字段，未填时提示输入。返回仍有效的页签缓存或只改显示格式时显示“已完成”，不再一边允许复制一边提示参数待更新。
