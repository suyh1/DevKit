# Git 仓库管理

桌面端与共享网页操作主机上的同一份 Git 工作树。主机需要 Git 2.32 或更新版本，并在运行 DevKit 的用户环境中配置提交身份、远端与凭据。浏览器只需登录共享工作台。

## 连接与发布

1. 在「共享栏目 → Git 仓库管理」登记已有工作树，或选择「克隆仓库」并填写 HTTPS、SSH 地址或主机本地仓库路径。选择父目录后，桌面在其中创建以仓库名命名的新目录，完成后自动登记。已存在的目标目录会提示重新选择。私有仓库使用主机已配置的非交互式凭据。
2. 在「仓库访问权限」设置默认权限及命名访客例外，再选择「发布到网页」。新登记仓库默认仅开放提交历史。升级前已登记的仓库沿用原有共享范围。
3. 在「局域网共享」开放 Git 栏目。命名访客可选择具体仓库，未获授权的仓库不会出现在清单、搜索或直接链接中。撤下共享或移除登记会保留磁盘上的文件。

| 仓库授权 | 范围 |
| --- | --- |
| 不可访问 | 隐藏仓库。如仅对特定人员开放，可将默认权限设为此项，再给命名访客单独授权。 |
| 仅提交历史 | 查看分支与提交历史、检索文件历史、比较提交。工作区、暂存区和贮藏内容仅向具有工作区权限的人提供。 |
| 查看历史、工作区和贮藏 | 读取已提交和未提交内容，包括未跟踪文件。 |
| 工作区读写／查看与远端同步／读写与同步 | 在上述读取范围上分别允许编辑、同步或两者。栏目总开关与当前访客的栏目授权仍同时生效。 |

## 从改动到推送

1. 点击文件路径审阅差异，点击未暂存文件行尾的 ＋ 将整个文件加入暂存区，点击已暂存文件行尾的 － 可撤销暂存。取消暂存会保留磁盘上的编辑，新文件会回到未跟踪状态。点击分组标题中的「暂存全部」或「取消暂存全部」处理整组；输入路径筛选后，按钮显示匹配文件数量，范围包含所有匹配页。勾选多个文件后，点分组标题中的「暂存所选」或「取消暂存所选」一次处理。工作区和暂存区各自每页显示 50 个文件。组首复选框选择本页可操作文件，跨页保留勾选。勾满一页可选择「选中全部 N 个匹配文件」，更改路径筛选会清除勾选。部分暂存的文件同时出现在两组，各自展示对应差异。也可在预览上方暂存整个文件，或在具体差异块上点击「暂存此块」。未暂存文件行和分组标题的回退按钮可放弃单项、所选或全部匹配改动。确认窗口会提示将删除的未跟踪文件数。预览后内容变化时，需要重新核对。子模块改动在其工作目录处理。在未暂存差异预览中，可确认「放弃文件更改」或「放弃此块」，已暂存的内容会保留。对未跟踪文件，确认删除会移除磁盘文件。新建、删除、模式变化、二进制和截断的文件使用整文件操作。
2. 服务端对补丁原始字节计算摘要。暂存时重新核对内容，并把核对过的补丁直接应用到索引。文件在另一台设备审阅期间被改写时，该次操作会停止，界面刷新差异。文件列表操作读取所选文件的当前补丁，已预览的文件额外核对最近一次预览摘要。整批补丁一次写入索引，任何一项无法应用时整批停止。单次补丁处理上限为 48 MiB，文本预览约 384 KiB。
3. 点击文件列表前操作栏的「提交…」，在弹窗核对目标本地分支与暂存数量。点「查看文件」可回到已暂存分组，已输入的说明会保留。输入说明后点击「提交到分支名」，也可按 Ctrl+Enter 或 ⌘+Enter。暂存区为空时可确认「暂存全部并提交」，范围包括未跟踪文件和被路径筛选隐藏的文件。勾选「修改上次提交」可编辑原提交说明，连同当前暂存改动一起替换上次提交。在本地分支选择「撤销上次提交」会把分支退回第一父提交，保留当前暂存区和磁盘内容，并将原提交说明填回输入框。撤销首次提交后可继续从暂存区提交。这两项操作只影响本机分支。桌面与网页使用同一份暂存区。
4. 需要发送时选择「提交后预览推送」，或从同一操作栏直接打开推送预览。界面显示来源分支、目标远端与分支、待发送数量及最近六条提交。数量来自本地远端跟踪记录，可先在「分支与同步」获取更新。确认后按预览的提交哈希执行普通推送。首次发布成功后设置上游。远端拒绝推送时，本地提交仍可在历史中查看。

## 合并、历史和贮藏

- **合并分支**。在「分支与同步」选取本地分支或远端跟踪分支，查看当前提交与目标分支的文件差异。在干净的工作区确认合并；可快进时直接更新，分叉时停在合并提交前。点击「查看冲突文件」，逐个选择当前版本、合入版本，或编辑 UTF-8 文本并保存结果。双方存在删除时也可选用删除的一侧。二进制或大型文件可选择一侧版本。处理完后点击「完成合并」，也可以「中止合并」恢复合并前状态。
- **阅读提交图**。彩色泳道展示父子关系，空心双圈标出合并提交。泳道跨页保留连线与颜色。HEAD、本地分支、远端分支和标签显示在对应节点旁，选中后可在详情中读到完整引用。按消息或文件筛选后展示匹配记录，比较起点可跨页保留。
- **查找旧提交**。历史每页 200 条，可按消息、作者、哈希或引用跨页检索。输入仓库相对路径查看该路径的提交历史。先选一条提交设为比较起点，再选另一条，右侧显示从起点到目标的差异。合并提交的单条详情相对第一父提交。
- **分支与标签**。从当前提交创建本地分支或轻量标签，工作区干净时可切换分支。获取、快进拉取与普通推送使用主机配置的远端。
- **贮藏**。保存暂存区、工作区和未跟踪文件，查看最近 100 条记录与差异，在干净工作区恢复选中的记录和原暂存状态。应用后保留贮藏记录。选择「弹出贮藏」会在成功恢复后删除记录，发生冲突时保留记录；「删除贮藏」只移除选中记录。

仓库写操作同时校验主机当前状态和权限。同一登记仓库的工作台写操作相互排斥。钩子与过滤器按主机配置运行，登记时应选择主机信任的工作树。

## 独立 Web 服务

在独立服务目录下用主机账号执行以下命令。登记工具使用同一份配置目录锁，运行前先停止使用该目录的服务。可通过 `DEVKIT_PROJECT_DATA` 指向已有配置目录。

```sh
node server/git-register.mjs publish "/srv/projects/example"
node server/git-register.mjs access "/srv/projects/example" history
node server/git-register.mjs access "/srv/projects/example" edit alice
node server/git-register.mjs list
```

设置 `DEVKIT_PROJECT_PASSWORD` 和 `DEVKIT_SHARE_GIT=true` 后运行 `node server/start.mjs`。需要时设置 `DEVKIT_GIT_EDIT=true`、`DEVKIT_GIT_SYNC=true`。后续可在停服后用 `node server/git-register.mjs unpublish "/srv/projects/example"` 撤下。登记清单位于配置目录的 `sharing/git-repositories.json`，仓库文件仍位于原工作目录。

## 设计与实现依据

| 参考项目 | 借鉴点 | 本项目取舍 |
| --- | --- | --- |
| [VS Code](https://code.visualstudio.com/docs/sourcecontrol/staging-commits) | 源代码管理视图用文件行 ＋／－ 处理整文件，点文件名查看工作区或暂存区差异。 | 使用已有主机 Git 与共享网页权限，文件复选框支持批量选择。 |
| [GitLens Commit Graph](https://github.com/gitkraken/vscode-gitlens#see-everything-in-one-place--commit-graph) | 并列泳道、引用标记和点选提交查看详情。 | 工作台用父提交哈希绘制 SVG，并在翻页时传递泳道状态。GitLens 的 Plus 功能单独授权，本项目独立实现。 |
| [GitHub Desktop](https://github.com/desktop/desktop)（MIT，约 2.2 万 Star） | Changes / History 双视图和文件列表联动差异检查器；上游桌面应用采用 TypeScript 和 Electron。 | 桌面与网页共用 React 检查器，避免浏览器依赖桌面 API。 |
| [Lazygit](https://github.com/jesseduffield/lazygit)（MIT，约 8.4 万 Star） | 工作区、分支、提交图与贮藏各有专门面板，后台使用 Git 的真实状态。 | 共用主机 Git CLI；窄屏将详情排在列表下方，保留分段控件的键盘操作。 |

两端共用同一管理器。桌面使用受信 IPC，网页由现有会话、栏目权限、逐仓库发布状态以及操作权限共同控制。文件状态使用 NUL 分隔输出，路径作为独立参数传给 Git；历史图按父提交哈希连线。实现依据见 [Git status](https://git-scm.com/docs/git-status)、[Git log](https://git-scm.com/docs/git-log) 和 [Git pull](https://git-scm.com/docs/git-pull)。

## 高频操作的界面设计

在仓库选择器旁打开「仓库访问权限」弹窗，可以设置默认权限和逐人例外，保存后生效。提交说明和冲突编辑框随输入自动增高，到达上限后在框内滚动。页面标题沿用共享工作台的字号。分支总览、推送按钮和选中项随主题配色及明暗模式变化，差异行用新增色和删除色区分。克隆、分支比较、提交与推送在弹窗中操作。仓库发布后，操作按钮切换为「撤下共享」。分支总览显示当前分支和最近提交。宽屏在操作栏下方并排展示文件与差异，窄屏在文件后展示差异。在工作区内滚动时，提交与推送入口吸附在顶部。推送预览弹窗列出目标与提交清单；本地提交和远端传输各自显示结果。分块暂存借鉴 Lazygit 的差异块操作，提交前核对文件和目标分支的组织方式参考 GitHub Desktop。底层使用 [Git apply](https://git-scm.com/docs/git-apply) 和 [Git merge](https://git-scm.com/docs/git-merge)。

## 验证入口

- `npm run test:git` 在临时工作树和本地裸远端检查登记、权限、首次提交、部分暂存、贮藏、分支合并、标签、获取、快进拉取和推送。另覆盖审阅后内容变化、分块暂存与撤销、冲突编辑与中止、首次发布、桌面克隆、旧提交分页检索及按访客隔离。
- `npm test` 包含总览对 Git 命令及现有 Git 文本工具的识别回归。
- `npm run build` 后运行 `node scripts/smoke-desktop.mjs --git-only`，从桌面选择目录、暂存、提交、发布，再由窄屏浏览器登录审阅，检查只读权限与布局，并验证编辑访客暂存与贮藏改动。
