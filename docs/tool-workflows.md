# 工具交互设计说明 · v1.9.2

首页、悬浮导航、分段筛选、加载和动效约定见 [界面设计说明](interface-design.md)；以下逐工具流程继续沿用。

本次逐项审查全部 45 个工具，依据输入长度、配置方式、结果语义和下一步操作选择布局。工具分类保持现有七类；统一的是导航、任务状态、复制、导入、导出、错误和取消操作。不同功能使用各自的工作区，不再默认套用两块等大的文本编辑器。

## 共同操作与边界

- 文档格式化成功后自动切到结果，原文单独保留；输入和输出都支持最大化。代码、配置、表格和匹配对照支持拖动分隔条与上下布局，其他工作区按用途布局。
- 输入修改或配置变化后，专属结果预览隐藏，显示保留的旧源码与待更新标记；复制、导出及继续处理都禁用，重新成功处理后恢复。失败、取消和恢复工作区也遵循此规则。成功输出 0 字符会明确显示“处理完成，结果为空”，仍可复制或导出空文本。
- 文件导入、拖入、清空、示例与撤销仍可使用。差异工具第一份文本支持文件导入，第二份通过独立编辑器粘贴。原生另存文件、整批复制和结果发送到新任务仍保留。
- 权限矩阵会保留 setuid / setgid / sticky 位。输入无效时矩阵禁用；清空后可从零勾选。勾选后需运行以更新结果。
- ULID 生成数量与解析标识分别保留草稿，切换不写入示例；首次从成功生成切到解析时可直接解析刚生成的真实标识。切回保留之前的数量；草稿随工作区一起保存。需要示例时主动点击“示例”。
- HTTP 表单只改动指定 method/URL 的 JSON 值，保留其他字段的原文、大整数、指数和 body 内重复字段；配置顶层重复字段需先在 JSON 中修正。结构化 body 在三种代码中均以原文字符串发送，缺少 Content-Type 时补 application/json，已有值优先。
- 继续处理保留完整结果，自动选用已知的源语言或分隔符：Java → 类型转 JSON 使用 Java，TSV → CSV 转 JSON 使用制表符。同一编解码工具接收自己的结果时使用反方向。进入新任务后仍可检查和调整设置。
- 原始文本、配置 JSON 和用户提供的 HTML 只作数据展示，不执行；HTTP 与 URL 工具不发起请求。输入数据仍默认仅在内存。
- 专属结果超过 300,000 字符时提示查看源码或导出；表格限制预览前 100 行、30 列，ULID 解析卡片限制前 100 项，导出始终使用完整处理结果。
- 独立任务与安全边界沿用现有实现。核对摘要的期望值仅保存在当前组件内存，不加入工作区快照。

## 实现与验证入口

`src/tool-experience.ts` 对所有注册工具声明功能流程，`ToolInput.tsx`、`HttpRequestInput.tsx` 与 `ToolResult.tsx` 负责专属交互。`ToolWorkspace.tsx` 保留公共任务操作，`tool-experience.css` 使用既有主题变量。

`npm test` 覆盖完整工具映射、权限特殊位、HEX / Base64 核对、真实算法输出预览、CSV 引号 / 换行与不可信文本转义。`npm run test:electron` 会实际运行全部 39 个文本/坐标工具，检查 6 个颜色工作区，并在浅 / 深色和 1440、1024、768、375 宽度下检查文本工具横向溢出；截图和逐项记录保存在 `artifacts/electron-smoke/`。Linux / 麒麟实际安装和启动需在目标系统验收。

v1.9.2 逐工具交互审查、修复和覆盖范围见 [审查清单](tool-interaction-audit-2026-10-24.md)。实际 Electron 回归对 38 个通用文本工具逐一核对系统剪贴板、原生保存的完整字节、发送结果的新任务与原任务保留，以及适用工具的清空/撤销和失效禁用；经纬度另跑三个页签，颜色另测实时输出和无效输入。

## 经纬度工作区

经纬度工具使用格式转换、圆周点计算、文本提取三个页签，分别保留输入和结果。椭球/球面算法、方向、单位、精度和复制边界见 [经纬度工具说明](geographic-coordinates.md)。结果支持单值、整列、全部与 CSV/TSV；待核对项不进入复制。输入变化禁止复制旧结果；格式设置可重排已有精确结果。
