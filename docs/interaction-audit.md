# 共享与全局交互一致性审查（2026-10-26）

## 为什么之前遗漏

此前将共享入口提升到桌面顶部后，验收仍沿用“项目中心就是共享入口”的旧假设，没有重新审视浏览器门户、三项服务的开放边界和权限依赖；测试也覆盖了旧行为，却没有质疑它是否合理。因此留下项目中心重复主题/退出、项目中心被强制开放、全局编辑扩散到全部服务的问题。这是设计和验收范围不足，不能用兼容旧实现解释为合理行为。

## 本次范围

审查了应用外壳、全局导航/快捷键、确认弹窗、工作区保存恢复、设置与本地偏好、三个共享模块、认证/权限/主机操作、独立服务启动和配置失败恢复。对普通工具的输入、结果、复制导出、任务关闭撤销和后台运行，复查公共组件并运行全套工具单测与桌面流程；逐工具既有基线见 [工具交互审查](tool-interaction-audit-2026-10-24.md)。本次重点是操作归属、默认值、权限依赖和失败后的实际状态，未逐一穷举所有算法输入。

## 已修复的问题

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 项目中心保留主题和退出，门户已有账户操作 | 同一全局动作重复、跨服务位置不一致 | 仅在门户顶部提供主题和退出，各服务只保留自身操作 |
| 项目中心随共享强制开放 | 无法只共享 Nginx 或 HTTP | 三项服务均独立选择，新配置不预选，零选择禁止启动 |
| 开放模块与全局权限分开 | 授权对象不清、修改一项可能扩大另一项能力 | 每张服务卡片内配置权限；未开放时收起权限，关闭清除授权 |
| 全局编辑附带 HTTP 发送、Nginx 运行要求编辑 | 数据修改与主机执行混淆 | 项目编辑/探测、Nginx 编辑/运行、HTTP 编辑/发送独立授权；主机逐路由校验 |
| 修改端口先停止旧服务 | 新端口占用或写盘失败导致健康服务中断 | 候选监听和持久化成功后再切换；失败保留原监听、设置、会话和表单草稿 |
| Nginx 只读状态可能隐式运行程序检测 | 查看动作越过执行权限边界 | 无运行权限时只读缓存检测结果，不启动程序；无法确认停止则拒绝改 pid/include |
| 浏览器生成代码是占位提示 | 看似有功能但无法完成任务 | 使用与桌面工具相同的离线 Fetch/Axios/cURL 生成器，可复制/导出，不发送请求 |
| GET/HEAD 的空正文能发送却无法生成代码 | 调试与代码生成规则不一致 | 空正文按无正文生成，非空正文仍拒绝，保留大整数原文规则 |
| 首次连接失败后登录被永久禁用 | 无法在页面内恢复 | 仅连接/登录进行中禁用，失败可重试连接或登录 |
| 会话失效后只有模块报错 | 草稿保留但缺少继续路径 | API 401 及项目会话失效统一提示重新登录，保持现有模块及草稿，可先导出；重新登录立即更新权限按钮 |
| 全局快捷键只屏蔽共享弹窗 | 模块弹窗内 Ctrl+K/Ctrl+Enter 可影响背景 | 任意原生模态弹窗打开时不执行全局快捷键 |
| 项目中心直接访问可选浏览器偏好存储 | 浏览器拒绝存储时可能阻断主机项目数据 | 偏好读写失败降级为会话内状态，仍能访问主机数据 |

同时修正了 Nginx 空状态对远程目录选择的误导，以及自动共享失败提示仍称“项目中心”的旧文案。API 响应“采用为响应示例”也跟随 HTTP 编辑权限，而不随发送权限授权。

## 兼容和明确边界

旧配置迁移保持原来已授予的实际能力，不会给原来关闭的服务增加权限；迁移后项目中心可以独立关闭。新权限模型使用版本化 services 配置，拒绝非法字段和布尔值；旧认证 API 别名保留，新门户使用独立 sharing 认证路径。

Nginx 的路径、配置、程序及所有命令都属于共享主机。HTTP 的 localhost、网络请求也属于共享主机；浏览器快速请求集合是访客本地数据。所有访客仍共用一套口令和服务权限，目前没有独立账号或按实例授权。

普通文本任务关闭已有撤销；设置导入/重置已有撤销；文件导入和替换已有输入保护。没有为了统一外观而额外给低影响动作加确认。颜色、图片等临时任务的保存范围沿用明确文档，不宣称持久保存未写入的内容。

## 设计参考

- [Hoppscotch](https://github.com/hoppscotch/hoppscotch)（MIT，活跃维护）：工作区角色和请求能力的边界有助于区分数据编辑与请求执行；本项目不引入其协作后端。
- [Portainer](https://github.com/portainer/portainer)（社区代码 zlib，活跃维护）：参考后端逐请求授权的思路；商业版 RBAC 不作为可复制实现。其 [授权检查代码](https://github.com/portainer/portainer/blob/develop/api/internal/authorization/access_control.go) 和 [授权修复公告](https://github.com/portainer/portainer/security/advisories/GHSA-gh7q-w9wj-5fww) 说明隐藏按钮不能代替真实接口校验。

仅借鉴能力边界与渐进展示，不复制代码、不新增依赖，也不引入独立账户系统。界面沿用现有主题、确认组件、键盘和移动布局。

## 验证

- `npm test`：工具逻辑、格式生成、输入保真、共享组件静态检查。
- `npm run test:desktop`、`npm run test:projects`、`npm run test:http`：桌面策略、项目数据、真实 HTTP 服务的模块独立性、编辑/执行组合、关闭服务的接口拒绝、会话、并发保存及取消隔离。
- `server/sharing-policy.check.mjs`：新默认、旧配置迁移、环境变量覆盖、三项服务分别单独启用、编辑/执行独立、失败重绑/持久化保留健康服务、只读 Nginx 不执行检测。
- `npm run test:nginx`：实例身份、备份、日志、共享文件、真实 nginx 检查/启动/重载/停止。
- `node scripts/smoke-sharing.mjs`：真实浏览器门户、主题/退出唯一性、单服务导航、HTTP 只编辑/只发送、代码生成不发送、失效后重新登录、禁用偏好存储、深浅主题和窄屏。
- `node scripts/smoke-desktop.mjs --sharing-settings-only`：默认未选、权限依赖、关闭清除、零选择禁止启动、同一面板、模块弹窗快捷键隔离、草稿保护、端口失败和响应式截图。
- `npm run docs:update`、`npm run test:docs`：生成 README 并检查同步。

自动验证使用临时配置目录，不修改真实项目、接口库或 Nginx 配置。截图位于 artifacts/electron-smoke 和 artifacts/sharing-smoke。目标局域网防火墙、多用户长时间并发、Linux/麒麟真实桌面未由本机 Windows 测试覆盖。本记录列出已审查边界，不表示所有未来输入或环境均不存在问题。

同端口切换“仅本机/局域网”时，系统无法同时绑定两个重叠地址，会短暂重绑；失败尝试恢复原监听，保留原授权和会话，但既有 TCP 连接可能中断。若其他进程抢占端口导致恢复失败，会报告原因并显示实际停止状态。不同端口应用先验证新监听再关闭旧监听。

本轮结果：188 项工具测试、4 项桌面策略、18 项项目测试、12 项 HTTP/共享测试、26 项 Nginx 测试、7 项文档测试均通过。完整桌面回归覆盖全部 46 个工具界面及三个工作区；末次项目与门户调整后分别重跑项目专项和门户专项通过。构建成功，保留原有分包体积与重复静态/动态导入提示。
