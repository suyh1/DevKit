# JAR 管理

在 Windows / Linux 桌面端侧栏选择与“Nginx 配置”平级的“JAR 管理”。本模块管理运行 DevKit 的本机进程，当前不通过局域网共享，不包含在独立共享服务的可访问模块中。

## 添加与运行

1. 点击“检测 Java”，自动依次检查 `JAVA_HOME/bin` 和 `PATH`，执行 `java -version` 显示版本与实际程序位置。未找到时安装对应架构的 JRE/JDK，或在 JAR 设置里指定绝对 Java 程序路径。DevKit 自身不需要 Java，也不会自动安装 Java。
2. 点击“添加 JAR”，选择已有 `.jar` 文件，自动获得绝对路径、文件名、工作目录和初始显示名称。可把显示名称改为“订单服务 · 测试环境”等便于识别的名字。
3. 可填写 Java 程序路径、JVM 参数、应用参数、日志模式和停止等待时间，并展开健康检查、日志保留、环境档案与崩溃重启设置。参数每行一个，原样传给 Java；包含空格的单个参数不额外加引号。JVM 参数写在 `-jar` 前，应用参数在 JAR 后，不填 `java`、`-jar`、主类或 Shell 重定向。参数、环境变量和路径保存在本机明文注册表。
4. 保存只登记，不运行。点击“启动”后，会先核对文件与当前状态，再执行 `java [JVM参数] -jar <绝对JAR路径> [应用参数]`。工作目录固定为 JAR 同级目录，相对配置文件可按此定位。
5. 通过列表启动、停止、重启，或展开“更多运行信息”选择“强制终止”“立即检查健康”。移除前须停止守护并关闭系统自启；移除只删除注册表记录，保留源 JAR、日志和运行文件。守护运行或等待重试时仅能修改显示名称，其他配置和环境档案需先停止。

## 文件规则

以 `/apps/order-service.jar` 为例，默认使用同目录的 `order-service.pid`、`order-service.log`，以及记录进程创建标识的 `order-service.pid.devkit.json`。Windows 使用相同规则，例如 `D:\apps\order-service.jar`。运行文件需有读写权限，不能用目录或符号链接代替。

- PID 文件仍是纯数字，便于与脚本排查方式一致；附加 JSON 是进程身份记录，勿在运行中修改或删除。
- 可以在设置中把文件名改为 `app.pid`、`app.log`，与 `manage.sh` 默认名称保持一致。只填文件名，路径固定在 JAR 同级。多个应用不能共用 PID、日志或身份文件；同一个 JAR 只能登记一次。
- 旧脚本只核对 PID 是否存活，本工具同时检查 Java 程序路径、`-jar` 的完整参数和进程创建标识。由原脚本启动、只有 PID 文件的进程会显示“待核实”，不会擅自终止或重复启动。先通过原脚本停止，再用工具启动。
- 文件模式由独立守护接收标准输出和错误，通过背压与串行写入追加日志，重启不清空历史。静默模式将这两类输出丢弃；应用自己的 Logback / Log4j 等日志配置仍由应用管理。
- 日志窗口按 UTF-8 读取最近 128 KB，自动刷新开启时每 3 秒更新；大文件只读取尾部，不整文件载入内存。使用其他字符编码的应用应在应用配置中统一日志编码。

## 状态监视与停止语义

列表展示显示名称、原文件名、绝对路径、文件大小、日志模式、进程状态、PID、运行时长、内存、CPU 和最后检测时间。启用自动刷新时每 5 秒更新；页面隐藏时暂停轮询，避免重复叠加请求。CPU 根据两次检测间的进程 CPU 时间计算，第一次没有样本时显示 `—`，多核使用率可超过 100%；内存是工作集 / RSS，不等同于 JVM 堆大小。

- **运行中**：PID、进程创建标识、Java 路径和 JAR 参数一致。
- **已停止**：没有运行记录，或由工具确认停止。
- **已退出**：启动过的进程已经退出，包括快速启动失败及失效 PID 文件；当前会话能获得退出码时一并显示，跨 DevKit 重启的退出码无法追溯。
- **待核实**：PID 内容非法、进程身份变化、旧脚本进程、PID 文件丢失但进程仍存在、无法读取进程信息或系统权限不足。此时拒绝进程控制，避免 PID 复用误杀。

“运行中”只说明进程存活，不代表端口已监听或业务健康。启动后会短暂观察，发现立即退出会报错；更慢的初始化失败由后续刷新和日志定位。

Linux 从 `/proc` 读取进程身份与资源数据，使用 `getconf CLK_TCK` 换算 CPU 时间与运行时长。停止先发送 `SIGTERM`，等待设置的 1–120 秒；超时保留进程和 PID，不自动升级为强杀。重启只在确认停止后启动。强制终止使用 `SIGKILL`。

Windows 使用系统自带 Windows PowerShell / CIM 查询进程，按 UTF-8 输出以支持中文路径。停止使用 `Stop-Process`，强制终止使用其 `-Force`，操作内再次核对进程创建时间。Windows 终止进程无法保证 Java shutdown hook 执行，界面会明确提示；需要业务级优雅关闭的应用应额外接入应用自己的关闭接口或服务机制。

## HTTP / TCP 健康检查

在 JAR 设置中选择 HTTP(S) 或 TCP，默认不检测。HTTP 使用 GET，要求精确的预期状态码（默认 200），不跟随重定向，不读取和保存响应正文；HTTPS 使用正常证书校验，不提供忽略证书选项。TCP 只测试目标主机与端口能否连接，不证明业务内容正确。

默认间隔 10 秒、超时 3 秒、启动宽限 30 秒、连续失败阈值 3 次。宽限内显示“启动宽限中”；宽限结束开始定时探测。一次成功即恢复健康，未达阈值的连续失败显示“检测波动”，达到阈值显示“不健康”。列表展示延迟，展开详情可查看检测原因与时间。“立即检查健康”可以越过宽限期主动检测。进程退出后不继续向目标发送探测。

健康失败只改变业务状态，不自动终止或重启进程；这与崩溃退出策略分开。所有探测从管理主机发出，目标由使用者显式配置，不使用系统 HTTP 代理。停止或重启时旧探测结果不覆盖新进程的状态。

## 日志轮转与保留

默认启用轮转：单文件 10 MB、归档保留 7 天、最多 10 份。可调整大小为 1–1024 MB、天数为 1–3650、归档数为 1–1000，或关闭轮转。仅对本工具接收的标准输出和标准错误生效。

达到大小上限时关闭日志句柄，将原日志重命名为 `<日志文件名>.devkit-<13位时间戳>-<UUID>.log`，再打开同名活动日志写入剩余字节，因此 Windows / Linux 都不依赖对 Java 正在占用的文件进行截断。写入流量较大时使用背压，避免无限排队占用内存。UTF-8 多字节字符可能横跨归档边界；按顺序合并可还原原始字节。

启动、每次轮转和每小时清理一次归档，超过天数或数量任一条件即删除。活动日志不按天数删除；只处理当前日志名对应且符合本工具命名规则的普通归档文件，不处理其他应用、手动备份、目录或符号链接。现有旧日志已经超出大小上限时，首次新写入会先归档它，不截断原内容。归档数上限之外另有一个活动日志文件。

## 环境变量与档案

“公共环境变量”每行 `KEY=value`，按第一个 `=` 分隔，值保留空格、`=`、`$` 等原文；不用 `export`，不额外加引号。空行和以 `#` 开头的注释行忽略。变量名须为字母 / 下划线开头的字母数字下划线，同一组最多 100 项；Windows 不允许仅大小写不同的重复变量名。

新应用预设开发、测试、生产三个空档案，可改名、增删（最多 20 个）并选择一个用于启动，也可仅使用公共变量。继承守护启动时的系统环境，再由公共变量、当前环境档案依次覆盖；不修改系统环境。示例：公共 `APP_NAME=order-service`，测试档案 `SPRING_PROFILES_ACTIVE=test`、`SERVER_PORT=8081`。切换档案先停止，保存后重新启动。系统环境改变后需停止守护并重新启动，重开 DevKit 才能继承其更新后的环境。

## 崩溃自动重启与守护生命周期

自动重启默认关闭。启用后默认初次等待 2 秒，后续按 2 倍增加，最多等待 60 秒，最多重试 5 次；每次连续稳定运行 60 秒后重置预算。这里的次数不含最初手动启动，达到上限后显示“重试已达上限”，需手动启动恢复。非零退出码、非手动信号退出或启动失败可以触发重试；正常退出（代码 0）、手动停止和无法确认的进程身份不会自动拉起。列表展示已使用次数、下一次重试时间和最近错误，等待重试时仍可点击“停止”取消。

每个启动的 JAR 有一个独立 Node 模式守护进程，复用 Electron 自带运行时，无需另装 Node。DevKit 退出不会停止 JAR 或守护，健康检查、日志轮转和崩溃拉起仍继续；再次打开恢复连接。同目录新增 `<PID文件名>.supervisor.json`，包含本机回环控制端口、随机令牌与进程创建标识。Linux 权限为 600，Windows ACL 仅允许当前用户与 SYSTEM；它不提供局域网接口。不要删除运行中的身份或守护记录。

手动停止先取消重试，再终止 Java、排空日志并关闭守护。若守护本身异常退出但 Java 仍活着，不擅自接管旧输出流或重复启动；先停止该进程，再重新启动恢复完整监视。操作系统注销、关机或会话清理可能终止进程，需持续系统托管时启用下节的开机模式。

注册表仍在实际配置目录 `jar/instances.json`，采用版本检查、原子写入和目录锁；守护运行快照位于 `jar/runtime/<应用ID>/`，系统自启安装记录位于 `jar/autostart/`。跨系统迁移后重新登记目标系统路径；不要在进程或自启仍运行时移动整个配置目录。

## 系统自启

列表点击“系统自启”，查看实际安装状态、选择触发方式，再明确点击“启用登录自启”或“启用开机自启”。安装前检查 JAR 与 Java 可用性，记录检测到的 Java 路径作为自启环境检测失败时的后备。注册不会立即运行；可以用列表“启动”测试。每次自启读取最新已保存的环境档案和策略，关闭 DevKit 不影响它。

- **Windows 登录模式**：使用当前用户的任务计划登录触发器及 Interactive 身份。
- **Windows 开机模式**：使用开机触发器及当前用户 S4U 身份，不保存密码；注册可能需要管理员权限，不保证访问依赖交互凭据的网络资源。任务使用隐藏窗口、无执行时长限制、忽略重复实例、允许电池运行，实际重试由 JAR 策略管理。
- **Linux 登录模式**：启用 `~/.config/systemd/user/`（遵循 `XDG_CONFIG_HOME`）下的用户服务，关联 `graphical-session.target`，要求桌面环境支持此目标；不适用于纯控制台登录或未接入该目标的桌面。这样已有 linger 也不会把登录模式变成开机触发。
- **Linux 开机模式**：用户服务关联 `default.target`，并执行当前用户的 `loginctl enable-linger`，使用户服务管理器在开机时启动并在注销后保持。系统可能要求授权。系统须支持 systemd 用户服务，失败会显示原因。

任务和服务使用配置目录摘要与应用 ID 命名并核对所有权标记，避免覆盖同名的其他任务。关闭自启只移除该应用的触发配置，不停止现有 JAR；先关闭自启再移除应用。Linux 不自动关闭 linger，以免影响同一用户的其他服务。移动、升级到不同路径或卸载 DevKit / Java 前先关闭自启，之后重新启用以更新可执行文件路径。当前没有自动管理员提权、系统重启测试或跨用户安装。

## 设计参考与后续功能

调研比较了 [Jpom](https://github.com/dromara/Jpom)（Java 服务端 / Agent，MulanPSL2，约 1.9k GitHub stars）与 [PM2](https://github.com/Unitech/pm2)（Node 守护进程，AGPL-3.0，约 43.3k stars；均为调研时页面值）。参考显式应用注册、独立启动参数和进程 / 业务状态分离的设计；没有复制其代码或新增依赖。Jpom 的 Windows 脚本说明强调通过日志判断启动结果；[PM2 环境变量问题](https://github.com/Unitech/pm2/issues/3672)提示重启时需要明确环境继承规则。本工具每次启动继承当前 DevKit 进程的环境，修改系统环境后需重开 DevKit。

扩展参考 [Uptime Kuma](https://github.com/louislam/uptime-kuma)（MIT，独立 HTTP/TCP 监视）、[pm2-logrotate](https://github.com/keymetrics/pm2-logrotate)（MIT，大小与保留策略）及 [PM2 重启策略](https://pm2.keymetrics.io/docs/usage/restart-strategies/)（指数退避）。系统集成依据 [Windows 任务身份](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskprincipal)与 [systemd linger](https://www.freedesktop.org/software/systemd/man/257/loginctl.html) 文档自行实现，无新增依赖或外部代码复制。后续可按需增加批量操作、历史健康趋势、应用专用优雅关闭接口。

验证：`npm run test:jar` 覆盖生命周期、PID 复用、环境覆盖、真实 HTTP/TCP、日志字节完整性与保留、退避策略及系统自启命令生成。完整 JDK 可额外编译并运行真实 JAR，验证独立守护、在线轮转、健康失败、重连、重试上限和停止取消；`DEVKIT_TEST_JAVA` 可指定 Java，或用 `JAVA_HOME` / `PATH`。`node scripts/smoke-desktop.mjs --jar-only` 覆盖桌面设置与 Electron Node 模式守护。`DEVKIT_TEST_STARTUP=1` 时可运行临时 Windows 任务注册/移除测试，测试结束清理自身创建的任务，不触发系统重启。
