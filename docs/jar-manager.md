# 服务管理

在应用的「更多操作与运行详情」中点击「关联手册」，可查找引用当前应用服务的团队文档。从这里新建文档会带入应用名称和所属主机的链接，也可以选择部署手册模板。详见[团队知识库](knowledge-base.md)。

点击“添加服务”，在表单内选择目标主机和启动方式。选择“Java JAR”后，可在 Java 程序路径下点击“检测 Java”，结果显示在表单内。编辑已有 JAR 时也可检测。有运行权限但无编辑权限的访客，可在已有 JAR 的“更多操作与运行详情”中点击“检测 Java”。

窄屏以卡片显示应用和状态，常用启停、日志与控制台操作直接可用。展开“详细信息与更多操作”查看路径、PID、内存、CPU、健康检查和维护操作。应用按本机、共享主机或目标主机分组，同时标明权限。远程列表独立更新，连接失败时可重试对应主机。

在 Windows / Linux 桌面端侧栏选择与“Nginx 配置”平级的“服务管理”。也可通过“局域网共享”开放“服务管理”，在浏览器或独立共享服务中使用。程序、工作目录与进程均属于实例所在的主机。桌面和共享网页使用相同的实例分组、表单和操作。

## 替换服务文件

在服务列表找到要更新的 JAR、可执行程序或解释器脚本，直接点击“停止”旁的“替换服务文件”。桌面和共享网页都从当前设备选文件，上传到所选实例所属主机，沿用登记的完整路径。远程 DevKit 主机也需要支持此功能；共享访问需要编辑和运行权限。

1. 核对主机和原路径，点击“停止服务并继续”。确认进程和守护均已停止后，再选择新文件。
2. 按需调整“在原目录保留带时间戳的备份”和“替换后启动服务”，两项默认勾选。
3. 点击“上传并替换”。上传完成后才覆盖原路径，弹窗显示启动结果及备份路径。取消或上传中断时，已停止的服务可从列表手动启动。若新文件启动失败，可重新上传旧版本；使用 `.bak` 备份恢复 JAR 时，先将备份副本的扩展名改回 `.jar`。

## 选择启动方式

| 启动方式 | 登记内容 | 目标主机环境 |
| --- | --- | --- |
| Java JAR | JAR 文件、Java 路径与 JVM 参数 | JRE 或 JDK |
| npm 项目 | 选择含有 package.json 的目录，读取脚本并选择 start、serve 或其他项目脚本 | 指定带 npm 的 Node.js 安装，或通过 PATH 查找 |
| 解释器脚本 | 选择解释器程序和入口脚本，参数每行一个。工作目录默认取脚本所在目录 | 已安装对应解释器，例如 Python 或 Node.js |
| 可执行程序 | 选择程序文件、工作目录和逐行参数。工作目录默认是程序所在目录 | Windows .exe 或带执行权限的 Linux 二进制文件，支持 Go 等编译产物 |

添加或编辑 Java JAR、npm 项目时，点击程序路径旁的“查找已安装版本”。列表按版本从高到低显示目标主机上的版本号和程序路径，点击一项即可填入表单，保存后生效。也可以输入绝对路径或点击“手动选文件”。留空沿用原有的自动查找规则。

查找范围包括主机账号的 PATH、已登记的运行时、常用安装目录和版本管理器目录，例如 Node.js 的 nvm、fnm、Volta，以及 Java 的 JAVA_HOME、SDKMAN!、Linux 的 /usr/lib/jvm 和 Windows 的 Java 注册表。指向同一程序的入口合并，同版本安装在不同目录会分别列出。自定义目录未列出时可手动选择。旧版目标主机仍可使用原有的路径配置。

三种检测都可在添加或编辑服务时使用，结果直接显示在对应字段旁。

- npm 项目点击“检测 Node.js 和 npm”，分别查看两者的版本和实际路径。可在“Node.js 程序路径（可选）”选择该服务使用的 node.exe（Windows）或 node（Linux）。保存时记录解析后的安装路径，检测、启动、重启和系统自启均由该 Node.js 调用配套 npm。启动脚本的 PATH 优先使用所选安装目录。所选安装缺少 npm 时会提示补齐或改选。路径留空时沿用目标主机、公共环境变量和当前环境档案的 PATH。可先检测再选择项目目录。
- 可执行程序选择文件后点击“检查可执行文件”。Windows 检查普通文件、.exe 扩展名及 PE 程序头，Linux 检查执行权限及 ELF 程序头或脚本声明的解释器。检测只读取文件，实际启动时才会加载运行依赖。

保存只登记。npm 启动保留 npm 的生命周期脚本，附加参数跟在双横线之后。服务使用目标主机上的现成依赖和构建产物。日志、控制台、健康检查、崩溃重试及自启使用同一套设置。新类型的运行文件默认按实例 ID 命名，允许同项目登记不同脚本。Windows 用 Job Object 管理子进程，Linux 管理前台服务及同进程组子进程。服务自身应以前台方式运行。

已有 JAR 继续使用原注册表、身份文件、日志路径及守护协议，升级后可接回由旧版启动的实例。可登记的类型以目标主机支持的版本为准。新版的共享权限“包含 npm、可执行程序与解释器脚本”默认关闭，可按主机和访客启用，独立服务可设置 DEVKIT_JAR_BACKEND=true。编辑和运行仍分别授权。

## 关联项目中心

展开服务的“更多操作与运行详情”，打开“关联项目”。可以新建已关联的项目，也可以为同一服务关联不同档案中的多个已有项目，点击“查看项目”会定位到对应档案和项目。在项目的“运维总览”中可查看服务状态并返回服务管理。项目只读访客可以查看已关联项目，有项目编辑权限才能更改关联。已有其他服务的项目可在项目编辑窗口更换关联。

## 管理其他电脑的应用服务

在桌面的“共享 → 局域网主机”保存 DevKit 共享或 SSH 连接，并勾选“服务管理”。回到服务管理，点击“添加服务”，选择目标主机，再选 JAR 文件、npm 项目目录、可执行程序或解释器与脚本。也可直接填写目标主机的绝对路径，如 `D:\apps\order.jar`、`/opt/order/order.jar`。JVM 参数、应用参数、环境档案、健康检查、重启策略等使用同一套表单，列表按主机分组。

通过 SSH 管理 Windows x64、Linux x64 或兼容的麒麟 ARM64 时，目标机安装适合业务 JAR 的 Java，并允许 SSH 执行命令。DevKit 会自动识别平台，使用 SFTP 或 SSH 命令通道上传自带的 Node.js 和管理程序。首次部署可能需要较长时间，后续连接复用已校验的运行时。业务 JAR 由 Java 启动，管理程序负责启停、日志、控制台、配置、健康检查、崩溃重启和系统自启。见 [局域网主机管理](workspace-sharing.md)。

DevKit 共享连接由目标端运行管理程序，复用该目标的实例登记。在中心机共享服务管理后，浏览器可按查看、编辑和运行权限操作本机及已登记的远程分组。

## 同目录配置文件

在桌面或共享网页顶栏点击“配置文件”，选择目标主机上的服务，核对顶部显示的配置目录，再从“同目录配置文件”中选一份。支持 UTF-8 的 `.yml`、`.yaml`、`.properties`、`.json`、`.xml`、`.toml`、`.ini`、`.conf` 和 `.cfg`，每份最多 512 KiB。YAML、JSON、XML 提供语法高亮。可用“刷新列表”重新读取目录，运行记录、日志、隐藏文件及文件符号链接排除在外。

“预览修改”显示草稿差异。“保存配置”对比读取时的内容哈希，检测到外部或其他客户端改动时保留草稿。确认磁盘版本后可继续编辑。“查看上一版”可将原始内容填回编辑器待保存。备份位于执行端的 `configs/jar/config-backups/`，SSH 连接使用目标用户的 `~/.devkit-ssh/managed/jar/config-backups/`。保存保留 UTF-8 BOM 及文件的主要换行格式。配置是否需要重启由应用自己的加载方式决定。

## 添加与运行 JAR

1. 点击“添加服务”，选择目标主机和“Java JAR”。留空 Java 程序路径，点击“检测 Java”，会自动依次检查 `JAVA_HOME/bin` 和 `PATH`，执行 `java -version` 显示版本与实际程序位置。未找到时安装对应架构的 JRE/JDK，或在 JAR 设置里指定绝对 Java 程序路径。DevKit 自身不需要 Java，也不会自动安装 Java。
2. 在同一表单选择已有 `.jar` 文件，自动获得绝对路径、文件名、工作目录和初始显示名称。可把显示名称改为“订单服务 · 测试环境”等便于识别的名字。
3. 可填写 Java 程序路径、JVM 参数、应用参数、日志模式和停止等待时间，并展开健康检查、日志保留、环境档案与崩溃重启设置。参数每行一个，原样传给 Java；包含空格的单个参数不额外加引号。JVM 参数写在 `-jar` 前，应用参数在 JAR 后，不填 `java`、`-jar`、主类或 Shell 重定向。参数、环境变量和路径保存在本机明文注册表。
4. 保存只登记，不运行。点击“启动”后，会先核对文件与当前状态，再执行 `java [JVM参数] -jar <绝对JAR路径> [应用参数]`。工作目录固定为 JAR 同级目录，相对配置文件可按此定位。
5. 通过列表启动、停止、重启，或展开“更多运行信息”选择“强制终止”“立即检查健康”。移除前须停止守护并关闭系统自启；移除只删除注册表记录，保留源 JAR、日志和运行文件。守护运行或等待重试时仅能修改显示名称，其他配置和环境档案需先停止。

远程启动后，本机列表会显示同一个进程与 PID；本机再次启动时，后端重新核实并提示“已在运行”，不会另起一个进程。远程、本机同时点击启动也会串行处理，页面状态尚未刷新不影响防重复校验。原 `manage.sh` 若继续使用，必须将 PID 文件名和目录统一，例如都为 JAR 同级 `app.pid`；否则脚本无法识别工具的默认 `<JAR名>.pid`。启用崩溃重启时，请从工具停止以先取消重试，直接从脚本杀进程可能触发自动拉起。

## silent / file / console 启动模式

设置中的“启动模式”提供三项，需先停止再切换：

| 模式 | 标准输出与错误 | 标准输入 |
| --- | --- | --- |
| silent | 丢弃 | 关闭 |
| file | 写入同目录日志，使用轮转与保留策略 | 关闭 |
| console | 实时显示到工具内控制台，不写标准输出日志文件 | 有控制权的用户可发送一行或 EOF |

console 启动成功后自动展开面板，也可以从列表“控制台”重新打开。桌面端与共享网页支持多人查看、搜索当前保留的输出行、复制、仅清空本页显示、暂停自动滚动和回到底部。输出通过独立守护持续接收，每次运行有独立代次与游标，最多保留 1 Mi UTF-16 字符；旧内容超出缓冲时会提示截断。关闭面板、切换页面、断线、退出共享登录或关闭 DevKit 都不会停止应用。重新打开可读取守护仍保留的输出；明确停止守护后内存输出不再可重取，console 不提供历史日志文件。应用自己的日志框架仍可独立写文件。

需要输入时点击“取得输入控制权”。同一时间只有一个客户端可以输入，其他人仍能查看，并显示当前控制者。关闭视图主动释放；断线、隐藏视图或不再刷新时，租约在 20 秒后到期。退出登录、关闭共享或修改权限会撤销对应共享会话的租约，本机控制权与共享会话分别处理。服务重启时清空本次输出、输入草稿和控制权，旧代次的输入不会发给新进程。

每次发送最多 4096 字符，按 UTF-8 编码并追加换行，直接写入服务的标准输入，不交给系统 Shell。发送 EOF 会关闭输入管道，需重新启动应用才能恢复。停止应用使用明确的停止按钮及现有平台停止语义；关闭面板不等同于脚本终端的 Ctrl+C。控制台不是 PTY，不提供系统终端、`System.console()`、全屏终端或交互式 Shell，应用应使用普通标准输入输出并统一 UTF-8 编码。

## 共享访问与权限

在“局域网共享”中独立开放“服务管理”。基础只读权限提供列表、运行状态和自启状态，环境变量值、档案变量值及 JVM / 应用参数由编辑权限保护。浏览器里的文件日志与控制台输出需开启“日志中心”并授予“服务日志”类别。输入控制权还需运行权限。运行权限同时允许检测 Java、启停重启、主动检查健康及管理系统自启。开放“包含 npm、可执行程序与解释器脚本”后，有编辑权限的访客可以检查程序文件，同时具有运行权限的访客还可检测 Node.js 和 npm。查找已安装版本需要编辑和运行权限，查找 Node.js 还需开放 npm 类型。服务关闭时直接访问 `/api/jar/*` 也无法操作。旧版共享设置迁移后，新增服务类型需显式授权。

桌面与共享网页使用同一个文件选择面板，可输入绝对目录、返回上级目录或从列表中选取文件。本机桌面还可点击“系统选择…”打开系统文件窗口。共享网页可填写实例所属主机上的绝对路径。选择已保存的远程主机时，可浏览其目录选择 JAR 文件、npm 项目目录、Node.js 或其他程序文件。独立服务设置 `DEVKIT_SHARE_JAR=true` 开放模块，`DEVKIT_JAR_EDIT=true` 和 `DEVKIT_JAR_CONTROL=true` 分别授权编辑与运行。所有接口复用已有口令、会话、同源校验和权限撤销逻辑。

## 文件规则

以 `/apps/order-service.jar` 为例，默认使用同目录的 `order-service.pid`、`order-service.log`，以及记录进程创建标识的 `order-service.pid.devkit.json`。Windows 使用相同规则，例如 `D:\apps\order-service.jar`。运行文件需有读写权限，不能用目录或符号链接代替。

- PID 文件仍是纯数字，便于与脚本排查方式一致；附加 JSON 是进程身份记录，勿在运行中修改或删除。
- 可以在设置中把文件名改为 `app.pid`、`app.log`，与 `manage.sh` 默认名称保持一致。只填文件名，路径固定在 JAR 同级。多个应用不能共用 PID、日志或身份文件；同一个 JAR 只能登记一次。
- 旧脚本只核对 PID 是否存活，本工具同时检查 Java 程序路径、`-jar` 的完整参数和进程创建标识。由原脚本启动、只有 PID 文件的进程会显示“待核实”，不会擅自终止或重复启动。先通过原脚本停止，再用工具启动。
- 文件模式由独立守护接收标准输出和错误，通过背压与串行写入追加日志，重启不清空历史。静默模式将这两类输出丢弃；应用自己的 Logback / Log4j 等日志配置仍由应用管理。
- 日志窗口按 UTF-8 读取最近 128 KB，自动刷新开启时每 3 秒更新；大文件只读取尾部，不整文件载入内存。使用其他字符编码的应用应在应用配置中统一日志编码。

## 状态监视与停止语义

列表展示显示名称、原文件名、绝对路径、文件大小、日志模式、进程状态、PID、运行时长、内存、CPU 和最后检测时间。启用自动刷新时每 5 秒更新；页面隐藏时暂停轮询，避免重复叠加请求。CPU 根据两次检测间的进程 CPU 时间计算，第一次没有样本时显示 `—`，多核使用率可超过 100%；内存是工作集 / RSS，不等同于 JVM 堆大小。

- **运行中**：已核实登记实例的进程身份。JAR 校验 Java 路径和 JAR 参数，npm 项目和可执行程序校验启动器及其启动参数。
- **已停止**：没有运行记录，或由工具确认停止。
- **已退出**：启动过的进程已经退出，包括快速启动失败及失效 PID 文件；当前会话能获得退出码时一并显示，跨 DevKit 重启的退出码无法追溯。
- **待核实**：PID 内容非法、进程身份变化、旧脚本进程、PID 文件丢失但进程仍存在、无法读取进程信息或系统权限不足。此时拒绝进程控制，避免 PID 复用误杀。

“运行中”只说明进程存活，不代表端口已监听或业务健康。启动后会短暂观察，发现立即退出会报错；更慢的初始化失败由后续刷新和日志定位。

Linux 从 `/proc` 读取进程身份与资源数据，使用 `getconf CLK_TCK` 换算 CPU 时间与运行时长。停止先发送 `SIGTERM`，等待设置的 1–120 秒；超时保留进程和 PID，不自动升级为强杀。重启只在确认停止后启动。强制终止使用 `SIGKILL`。

Windows 使用系统自带 Windows PowerShell / CIM 查询进程，按 UTF-8 输出以支持中文路径。停止使用 `Stop-Process`，强制终止使用其 `-Force`，操作内再次核对进程创建时间。Windows 终止进程无法保证 Java shutdown hook 执行，界面会明确提示；需要业务级优雅关闭的应用应额外接入应用自己的关闭接口或服务机制。

Windows 的 Java 启动器还受其版本和系统原生字符集影响：旧版 JDK 在英文代码页下可能将中文路径转换成 `?`，这不是 `-Dfile.encoding=UTF-8` 能修正的。若日志显示 `Unable to access jarfile` 且路径字符失真，请使用该系统字符集可表示的路径（例如英文目录与文件名），或在系统区域设置中启用 UTF-8 后重启。工具不会自动修改系统区域设置。测试始终验证空格路径；Windows JDK 17 的英文 CI 使用英文运行文件名，中文路径在 Linux 与本地支持的字符集环境中验证。

## HTTP / TCP 健康检查

在服务设置中选择 HTTP(S) 或 TCP，默认不检测。HTTP 使用 GET，要求精确的预期状态码（默认 200），不跟随重定向，不读取和保存响应正文；HTTPS 使用正常证书校验，不提供忽略证书选项。TCP 只测试目标主机与端口能否连接，不证明业务内容正确。

默认间隔 10 秒、超时 3 秒、启动宽限 30 秒、连续失败阈值 3 次。宽限内显示“启动宽限中”；宽限结束开始定时探测。一次成功即恢复健康，未达阈值的连续失败显示“检测波动”，达到阈值显示“不健康”。列表展示延迟，展开详情可查看检测原因与时间。“立即检查健康”可以越过宽限期主动检测。进程退出后不继续向目标发送探测。

健康失败只改变业务状态，不自动终止或重启进程；这与崩溃退出策略分开。所有探测从管理主机发出，目标由使用者显式配置，不使用系统 HTTP 代理。停止或重启时旧探测结果不覆盖新进程的状态。

## 日志轮转与保留

默认启用轮转：单文件 10 MB、归档保留 7 天、最多 10 份。可调整大小为 1–1024 MB、天数为 1–3650、归档数为 1–1000，或关闭轮转。仅对本工具接收的标准输出和标准错误生效。

达到大小上限时关闭日志句柄，将原日志重命名为 `<日志文件名>.devkit-<13位时间戳>-<UUID>.log`，再打开同名活动日志写入剩余字节，因此 Windows / Linux 都不依赖对 Java 正在占用的文件进行截断。写入流量较大时使用背压，避免无限排队占用内存。UTF-8 多字节字符可能横跨归档边界；按顺序合并可还原原始字节。

启动、每次轮转和每小时清理一次归档，超过天数或数量任一条件即删除。活动日志不按天数删除；只处理当前日志名对应且符合本工具命名规则的普通归档文件，不处理其他应用、手动备份、目录或符号链接。现有旧日志已经超出大小上限时，首次新写入会先归档它，不截断原内容。归档数上限之外另有一个活动日志文件。

## 环境变量与档案

“公共环境变量”每行 `KEY=value`，按第一个 `=` 分隔，值保留空格、`=`、`$` 等原文；不用 `export`，不额外加引号。空行和以 `#` 开头的注释行忽略。变量名须为字母 / 下划线开头的字母数字下划线，同一组最多 100 项；Windows 不允许仅大小写不同的重复变量名。

新应用预设开发、测试、生产三个空档案，可改名、增删（最多 20 个）并选择一个用于启动，也可仅使用公共变量。继承守护启动时的系统环境，再由公共变量、当前环境档案依次覆盖；不修改系统环境。示例：公共 `APP_NAME=order-service`，测试档案 `SPRING_PROFILES_ACTIVE=test`、`SERVER_PORT=8081`。切换档案先停止，保存后重新启动。系统环境改变后需停止守护并重新启动，重开 DevKit 才能继承其更新后的环境。

## 崩溃自动重启与守护生命周期

自动重启默认关闭。启用后默认初次等待 2 秒，后续按 2 倍增加，最多等待 60 秒，最多重试 5 次；每次连续稳定运行 60 秒后重置预算。这里的次数不含最初手动启动，达到上限后显示“重试已达上限”，需手动启动恢复。非零退出码、非手动信号退出或启动失败可以触发重试；正常退出（代码 0）、手动停止和无法确认的进程身份不会自动拉起。列表展示已使用次数、下一次重试时间和最近错误，等待重试时仍可点击“停止”取消。

每个启动的服务有一个独立 Node 守护进程。SSH 目标使用中心端部署的便携运行时，桌面本机使用 Electron 自带运行时，独立共享服务的本机实例使用服务主机的 Node.js 24+。DevKit 退出或 SSH 断开后，守护进程仍执行健康检查、日志轮转、控制台输出和崩溃拉起，重新连接可接管原进程。同目录新增 `<PID文件名>.supervisor.json`，包含本机回环控制端口、随机令牌与进程创建标识。Linux 权限为 600，Windows ACL 仅允许当前用户与 SYSTEM；网页经共享主机 API 的会话与权限检查后转发。旧版已登记的自启项仍引用创建时的运行时路径。若计划移除旧版使用的系统 Node，请先在新版 DevKit 重新保存该应用的自启设置。

手动停止先取消重试，再停止服务进程、排空日志并关闭守护。若守护本身异常退出但服务仍在运行，不擅自接管旧输出流或重复启动；先停止该进程，再重新启动恢复完整监视。操作系统注销、关机或会话清理可能终止进程，需持续系统托管时启用下节的开机模式。

注册表仍在实际配置目录 `jar/instances.json`，采用版本检查、原子写入和目录锁；守护运行快照位于 `jar/runtime/<应用ID>/`，系统自启安装记录位于 `jar/autostart/`。跨系统迁移后重新登记目标系统路径；不要在进程或自启仍运行时移动整个配置目录。

## 系统自启

列表点击“系统自启”，查看实际安装状态、选择触发方式，再明确点击“启用登录自启”或“启用开机自启”。安装前检查该服务的启动配置。JAR 还会记录检测到的 Java 路径，供自启时回退使用。注册不会立即运行；可以用列表“启动”测试。每次自启读取最新已保存的环境档案和策略，关闭 DevKit 不影响它。

- **Windows 登录模式**：使用当前用户的任务计划登录触发器及 Interactive 身份。
- **Windows 开机模式**：使用开机触发器及当前用户 S4U 身份，不保存密码；注册可能需要管理员权限，不保证访问依赖交互凭据的网络资源。任务使用隐藏窗口、无执行时长限制、忽略重复实例、允许电池运行，实际重试由服务的重启策略管理。
- **Linux 登录模式**：启用 `~/.config/systemd/user/`（遵循 `XDG_CONFIG_HOME`）下的用户服务，关联 `graphical-session.target`，要求桌面环境支持此目标；不适用于纯控制台登录或未接入该目标的桌面。这样已有 linger 也不会把登录模式变成开机触发。
- **Linux 开机模式**：用户服务关联 `default.target`，并执行当前用户的 `loginctl enable-linger`，使用户服务管理器在开机时启动并在注销后保持。系统可能要求授权。系统须支持 systemd 用户服务，失败会显示原因。

任务和服务使用配置目录摘要与应用 ID 命名并核对所有权标记，避免覆盖同名的其他任务。关闭自启只移除该应用的触发配置，正在运行的服务会继续运行；先关闭自启再移除应用。Linux 不自动关闭 linger，以免影响同一用户的其他服务。移动、升级到不同路径或卸载 DevKit / Java 前先关闭自启，之后重新启用以更新可执行文件路径。当前没有自动管理员提权、系统重启测试或跨用户安装。

## 设计参考与后续功能

调研比较了 [Jpom](https://github.com/dromara/Jpom)（Java 服务端 / Agent，MulanPSL2，约 1.9k GitHub stars）与 [PM2](https://github.com/Unitech/pm2)（Node 守护进程，AGPL-3.0，约 43.3k stars；均为调研时页面值）。参考显式应用注册、独立启动参数和进程 / 业务状态分离的设计；没有复制其代码或新增依赖。Jpom 的 Windows 脚本说明强调通过日志判断启动结果；[PM2 环境变量问题](https://github.com/Unitech/pm2/issues/3672)提示重启时需要明确环境继承规则。本工具每次启动继承当前 DevKit 进程的环境，修改系统环境后需重开 DevKit。

扩展参考 [Uptime Kuma](https://github.com/louislam/uptime-kuma)（MIT，独立 HTTP/TCP 监视）、[pm2-logrotate](https://github.com/keymetrics/pm2-logrotate)（MIT，大小与保留策略）及 [PM2 重启策略](https://pm2.keymetrics.io/docs/usage/restart-strategies/)（指数退避）。系统集成依据 [Windows 任务身份](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskprincipal)与 [systemd linger](https://www.freedesktop.org/software/systemd/man/257/loginctl.html) 文档自行实现，无新增依赖或外部代码复制。后续可按需增加批量操作、历史健康趋势、应用专用优雅关闭接口。

验证：`npm run test:jar` 覆盖生命周期、PID 复用、环境覆盖、真实 HTTP/TCP、日志字节完整性与保留、退避策略及系统自启命令生成。完整 JDK 可额外编译并运行真实 JAR，验证独立守护、在线轮转、健康失败、重连、重试上限和停止取消；`DEVKIT_TEST_JAVA` 可指定 Java，或用 `JAVA_HOME` / `PATH`。`node scripts/smoke-desktop.mjs --jar-only` 覆盖桌面设置与 Electron Node 模式守护。`DEVKIT_TEST_STARTUP=1` 时可运行临时 Windows 任务注册/移除测试，测试结束清理自身创建的任务，不触发系统重启。

强制终止的确认窗口列出目标主机、实例和未保存数据的风险。可从滑条左端拖至最右并松开，也可用键盘聚焦确认按钮。普通停止仍使用原有确认流程。
