# 共享工作台扩展建议

基于 HTTP 调试、项目中心、Nginx 配置、JAR 管理，建议优先发展可跨电脑协作的完整工作流。监控中心首期已实现（定时检测、历史、故障恢复、维护窗口、项目/JAR关联和登录后的共享查看），详见[监控中心说明](monitor-center.md)；日志中心也已实现首期（见[日志中心说明](log-center.md)）；外部通知、全量历史日志检索及其他扩展仍为规划。

## 先补齐现有栏目的连接

建议先让项目中心成为关联入口：每个项目可以关联HTTP集合、Nginx实例、JAR应用及后续监控项，从一个页面跳转排障。关联不改变现有独立档案语义，也不隐式联动启停。跨模块自动发布、重载或回滚放到后续阶段设计。

共享基础能力建议增加实名用户/个人会话、按项目或资源授权及操作审计，再逐步替代目前按服务划分的统一口令权限。新增栏目应同时覆盖桌面、共享网页和独立Node服务，并延续查看、编辑、执行分开授权的现有约定。

先做监控、API自动化和统一日志，能复用已有请求、健康检查、日志和共享基础；容器及数据库涉及新的运行依赖，适合在前述工作流稳定后开发。
