# DevKit · 开发者工具箱

DevKit 是中文界面的本地开发工作台，提供 **{{CATEGORY_COUNT}} 类、{{TOOL_COUNT}} 个离线工具**，以及可通过局域网共享的项目中心、Nginx 配置与实例管理、接口设计、文档与调试一体化工作台。桌面端基于 Electron + React + TypeScript，Windows、Linux amd64 与 Linux ARM64 共用内置 Chromium，无需目标电脑另装 Node.js、Python、Java、WebView2 或 WebKitGTK。运行 Nginx 实例需单独安装对应系统和架构的 nginx。

当前版本：**v{{VERSION}}**。工具输入和结果默认只保存在内存中；偏好、收藏、主动保存的 API 项目、HTTP 请求集合、JAR 管理和项目中心配置按各自规则保存。项目中心共享、手动入口检测和显式发送的 HTTP 调试请求会按用户操作使用网络，无遥测和远程字体。运行 JAR 应用需要另装 Java。

## 开始使用

1. 根据系统选择安装包：Windows 使用 `DevKit_{{VERSION}}_x64-setup.exe`；Linux amd64 / ARM64 使用对应架构的 `.deb`。发行合集目录为 `artifacts/release-{{VERSION}}/`。
2. 启动后在总览中搜索工具名称或用途，或按 `Ctrl/Cmd + K` 打开全局搜索。工具可载入示例、粘贴文本或导入本地文件，处理后复制、导出或继续送入其他工具。
3. 需要管理开发、测试、生产入口时，打开侧栏的“项目中心”，添加项目与配置档案；其他电脑需要访问时，使用顶部工具栏的“局域网共享”统一开放模块和设置权限。
4. 需要维护本机 Nginx 时，打开与项目中心平级的“Nginx 配置”，登记主文件、附属文件、运行目录与 nginx 程序。默认按字段编辑，也可切换全文；保存后检查配置，再启动或重载。
5. 打开“HTTP 调试”，在“接口项目”中维护项目、目录、接口定义和环境变量，切换接口设计、文档与运行调试；支持响应 Schema 校验、OpenAPI/Swagger JSON/YAML 导入导出、Markdown 文档和完整项目备份。原来的“快速请求”保留集合、历史和代码生成流转。全部界面与数据可离线使用，只有点击发送才访问目标服务，详见 [HTTP/API 工作台说明](docs/http-workbench.md)。
6. 点击窗口关闭按钮，选择“退出软件”或“最小化到托盘”，可勾选记住选择；在“偏好设置 → 窗口与托盘”中随时改回每次询问。托盘菜单可打开或退出，真正退出时仍检查未保存草稿。

Windows 解压版需要保留整个应用目录，再运行 `devkit.exe`。Windows 安装包当前未配置代码签名。Linux / 麒麟离线安装、基础库检查和启动排查见 [麒麟 V10 部署说明](docs/kylin-offline-install.md)。

### 经纬度处理

“时间与数值 → 经纬度工具”在同一工具内提供十进制度/度分秒互转、圆心与半径的四方向圆周点计算、混合文本中的度分秒坐标提取。圆周算法可选 WGS84 椭球测地线（默认）或球面大圆；支持单值、坐标对、整列和 CSV/TSV 复制/导出，各页签分别保留参数与结果。

粘贴坐标对“填入经纬字段”及提取后“用作圆心”保留角度原文，只有主动转换才改变表示。结果的十进制度/度分秒旁分别复制对应数值。格式转换不改变坐标基准；圆周方向为起始方位角，正东/正西终点纬度可能变化。文本提取不跨无关段落拼凑坐标，无法确认的片段另列供核对。输入格式、精度、半径及复制边界见 [经纬度工具说明](docs/geographic-coordinates.md)。

## 工作台与文件处理

- **独立任务**：最多 {{MAX_TASKS}} 个任务，同一工具可打开多份输入；切换保留编辑内容、光标和滚动位置。任务可后台处理或取消，修改输入后保留旧结果并标记待更新，失败后可重试。

- **工作空间外观**：悬浮导航连接各工作台模块与收藏，窄屏均分图标入口并保留可访问名称；首页以 Bento 区块展示快捷工具、内容识别和配色入口；分段切换全部 / 收藏 / 最近使用。默认主题浅色采用中性灰白表面、深灰文字与蓝色强调，深色采用石墨灰背景、柔白文字与雾蓝强调色；两种模式均关闭首页 Aurora 光晕；成功、警告、错误分别使用绿色、琥珀色和柔红色。可暂停的类别滚动带、真实加载骨架和柔和过渡兼容减少动态效果设置，详见 [界面设计说明](docs/interface-design.md)。
- **按功能设计的工作区**：格式化使用单文档「编辑原文 / 查看结果」切换；编解码使用上下流程；代码与配置转换保留可调整分栏；差异对比使用并排双输入和下方差异。全部 {{TOOL_COUNT}} 个工具的逐项设计见 [工具交互设计说明](docs/tool-workflows.md)。
- **查询、计算与解析**：状态码搜索与快捷码、时间字段卡片、子网位图、chmod 权限矩阵、Cron 五字段拆解与 UTC 时间线、JWT 分区、URL 参数表、文本统计指标。HTTP 请求代码提供方法 / URL 表单与配置 JSON 切换；Headers / body 在 JSON 中编辑。

- **过渡与反馈**：弹窗、分类浮层、导航页签、折叠区、列表、HTTP 状态、颜色与真实加载骨架使用统一过渡；复制完成由剪贴板实际结果驱动。模式切换保留编辑器，系统“减少动态效果”时直接显示最终状态。覆盖清单与边界见 [界面动效说明](docs/ui-motion.md)。

- **批量 Mock**：从 JSON 示例或常用 Schema 子集生成 1–1,000 份中文数据，支持固定种子、字段规则与 JSON/CSV 导出。规则、支持的 Schema 范围与资源限制见 [数据对比与 Mock](docs/data-workbench.md)。

- **工作区与偏好**：可主动保存、恢复文本任务；默认排除密码、JWT、HMAC，颜色任务和图片不写入工作区。主题风格提供默认、极简扁平、自然有机、编辑杂志、新野兽派、柔和界面、macOS 毛玻璃、现代渐变、复古怀旧，每套独立支持浅色、深色、跟随系统；原有深浅配色保留为默认主题。桌面设置和共享网页均可选择，另有密度、启动工具及设置 / 收藏导入导出。

## 颜色管理

取色、格式转换、调色板、渐变、对比度和混色共用当前主颜色及最多 40 个本地收藏色。支持 HEX / HEXA、RGB、HSL 输入，显示 HSV / CMYK 分量，配色可导出 CSS 变量或 JSON，渐变可导出 CSS。

屏幕吸管在运行环境支持时启用；也可使用色板或本地图片取色。图片支持 PNG / JPEG / WebP / BMP，最大 20 MB、2000 万像素，可按坐标取色，不上传图片。颜色换算基于 sRGB，CMYK 不含印刷 ICC 配置；HSL 色阶不保证感知均匀。对比度检查提供 WCAG 2.2 的 AA / AAA 阈值判断。

## Nginx 配置

- **多实例与多文件**：Windows / Linux 每个实例均可登记一个主配置及多个附属文件，按 include 递归发现（包括通配符）或手动添加。没有文件时选择“新建配置”，指定目录、主/附属文件名和端口，生成已互相引用的双文件配置及运行目录，创建后直接进入编辑；已有同名配置不会覆盖。导入已有文件时仅登记，不自动改写 include。
- **字段与全文编辑**：默认按 `http` / `server` / `location` 等层级显示字段，提供端口、域名、静态目录、代理目标、请求头、日志、PID 等说明，保留未知指令、重复指令、注释和原有布局。可新增/删除指令或配置块；主文件与附属文件的全文模式均提供 Nginx 语法高亮，区分指令、参数、变量、数字和注释，适配深浅主题，并支持行号、查找与撤销。
- **新手填写提示**：仅在输入字段旁保留“？”，支持悬停、点击和键盘聚焦查看中文用途、示例及路径基准，点击外部或按Esc关闭；操作按钮、配置块标题及汇总说明不再额外显示提示。
- **实例删除**：实例列表和顶部均提供明确的删除入口。有草稿也可发起删除并确认放弃；删除其他实例保留当前草稿，删除当前实例切换相邻项，删除最后一项回到空状态。删除只移除实例记录，保留配置、备份及已有Nginx进程。
- **文件保存与恢复**：配置原地保存，保存前检查内容哈希并备份原文件，原子替换遇到Windows临时占用时有上限重试；外部修改时要求重新读取合并。备份可载入草稿核对后保存；保存不会自动重载。配置须为 UTF-8，保留 BOM 和现有换行。
- **引导与草稿保护**：尚未添加实例时，直接选择“新建配置”或“导入已有文件”，Windows/Linux均支持主文件与多个附属文件。实例表单按基本信息、配置/目录组织，底部操作栏固定；仅实际修改后才提示未保存。取消编辑、关闭应用和重新加载使用统一的主题确认弹窗，“继续编辑”保留输入与服务连接。
- **本机运行控制**：自动检测 PATH / 常见路径，也可指定 nginx 程序与运行目录。使用主文件的 `-c` 参数检查、启动、`-s quit` 优雅停止及 `-s reload` 重载；启动/重载前自动执行 `-t`。状态依赖 PID 文件与进程身份，无法确认时拒绝停止或重载。
- **目录准备与固定操作区**：检查、启动、重载时自动补齐日志/PID父目录、临时及缓存目录，并列出新建结果；不覆盖文件、不伪造配置或证书。实例信息、运行操作和反馈随配置滚动吸顶，以紧凑状态保留主要操作，可展开详情；适配窄屏与减少动态效果设置。
- **Windows / Linux**：共用同一套功能；配置应符合目标系统的路径、模块和权限。可编辑其他系统的文件，运行操作仅对匹配系统启用。每个并行实例需不同 PID 路径和监听端口；进程不会随 DevKit 退出而停止。局域网页面可按授权远程填写实例与主机路径、新建配置、编辑文件和查看日志；所有文件操作均发生在运行 DevKit 的主机，程序检测、检查、启动、停止和重载需另开运行权限。

完整步骤、路径规则、命令和权限排查见 [Nginx 配置说明](docs/nginx.md)。

接口工作台采用本项目原生组件与主题。方案调研、支持边界见 [API 工作台设计](docs/api-workspace-design.md)，本次新增依赖的许可证见 [API 第三方声明](docs/api-third-party-notices.md)。

## JAR 管理

与“Nginx 配置”平级的本机应用列表，支持 Windows / Linux 选择 JAR、自动获取目录与文件名、自定义显示名称、检测 Java 或指定每个应用的 Java 路径。可填写 JVM / 应用参数及公共环境变量，维护开发、测试、生产等档案并选择启动环境；档案覆盖公共变量，不修改系统环境。启动、停止、重启时校验进程身份，列表显示运行时间、PID、工作集 / RSS 内存及采样 CPU，默认每 5 秒刷新。

PID 和日志均放在 JAR 同级，默认 `<JAR名>.pid`、`<JAR名>.log`，可改为脚本的 `app.pid` / `app.log`；多应用禁止文件冲突。独立守护接收标准输出和错误，默认按 10 MB 轮转、归档保留 7 天且最多 10 份；仅清理本工具生成的归档。支持静默模式及最近 128 KB 日志定时查看。Linux 先 TERM 等待退出，超时可单独强制终止；Windows 终止无法保证 Java 关闭钩子执行。

可配置 HTTP(S) 预期状态码或 TCP 连接检查、检测间隔、超时、启动宽限与连续失败阈值，单独展示业务健康，不把进程存活当作就绪；健康失败不自动重启。崩溃自动重启默认关闭，启用后按指数退避、次数上限和稳定时间重置执行，手动停止取消重试，正常退出不拉起。退出 DevKit 后守护仍继续健康检测、轮转与重试。

“系统自启”支持 Windows 任务计划的当前用户登录 / 开机触发，以及 Linux systemd 图形会话登录 / 开机 linger；安装后显示系统实际状态，错误不伪装成成功。安装自启不立即运行，关闭自启不停止现有进程。开机模式可能要求系统权限，Linux 关闭单个应用自启不关闭其他用户服务使用的 linger。注册表保存在 `configs/jar/instances.json`（以实际配置目录为准），不开放局域网共享。Java 安装、旧脚本迁移、守护生命周期和平台限制见 [JAR 管理说明](docs/jar-manager.md)。

## 项目中心

项目中心按独立档案维护不同方案的项目入口，桌面与局域网网页共用同一份主机数据。

- **项目与档案**：每个配置档案独立拥有项目与变量；项目维护名称、档案内唯一编码、分组、说明、HTTP(S) 地址模板、查询参数和启停状态。新建档案为空，复制档案产生独立副本；增删改仅影响所属档案。切换档案只影响当前使用者。
- **管理与预览**：支持搜索、分组、排序、紧凑卡片 / 列表、复制项目 / 档案，以及图标与文字统一对齐的批量操作栏，支持勾选后的批量启停、批量删除（确认时列出筛选外勾选项，删除前自动备份）。项目卡片直接提供删除入口；编辑时展示 URL 组成及当前档案的解析结果，有修改时提供草稿退出保护。
- **导入导出与恢复**：支持 JSON 导出、导入影响预览、合并或替换；保存时检查版本冲突。自动保留最近 30 份快照，支持命名备份、恢复预览，导入和恢复前自动备份。
- **对比方案**：选择 2–4 个档案，按项目编码对齐并标记缺少的项目，比较完整配置、最终入口与变量，支持只看差异和 JSON 报告导出。
- **手动探活**：项目卡片/列表提供单项“探活”，当前配置提供“全部探活”（包含筛选外项目），也可检测勾选项。停用项目跳过，逐项展示正常/异常、状态码、耗时及检测时间，并汇总进度；结果仅在当前页面临时保留，不自动轮询。请求由主机发起，启停只控制入口状态，不启动或停止系统服务。
- **局域网访问**：顶部工具栏提供全局“局域网共享”与实时状态；项目中心、Nginx、HTTP 页面可通过“共享设置”快捷打开同一面板。桌面端开启共享后，其他电脑通过主机 IP / 端口进入共享工作台，使用口令登录。三个服务均独立选择，首次不预选；权限在对应服务内设置，编辑与执行分别授权。浏览器顶部统一切换主题及退出登录，关闭服务会清除其权限。旧配置保留已有授权，应用失败保留原服务与会话。可设置下次启动自动共享。详见 [共享工作台](docs/workspace-sharing.md)。

### 配置保存与迁移

| 运行方式 | 默认配置位置 |
| --- | --- |
| Windows 安装版 / 解压版 | `devkit.exe` 同级的 `configs/` |
| Linux 安装版 | `/opt/devkit/configs/` |
| 独立 Node 服务 | 解压根目录的 `configs/`，与 `server/` 同级 |
| 源码桌面运行 | 仓库根目录的 `configs/` |

`configs` 中每个档案对应一个 `profile-<编码 ID>.json`，独立保存项目与变量；`projects.json` 保存索引、版本与快照，共享设置及加盐口令哈希另存。旧数据自动展开为独立档案并保留原始备份；API 项目、环境和上次保存快照位于 `configs/http/api-workspace.json`，整目录复制时一起迁移；桌面 Nginx 实例注册表和原文件备份位于 `configs/nginx/`，实际配置文件仍在原路径。首次启动会在新位置无数据时迁入旧版项目配置并保留原件；已有新配置优先，升级和卸载保留配置目录。

迁移时关闭来源与目标应用 / 服务，备份目标配置后，复制整个 `configs` 到新安装目录并确保普通用户有写入权限。只导出项目 JSON 不会包含共享口令和历史快照。两边数据需要合并时使用界面的导入预览。

### 独立服务部署

适合常驻主机：解压 `DevKit_ProjectCenter_{{VERSION}}_node24.zip`，**服务端准备 Node.js 24+**，无需 `npm install`；浏览器客户端无需安装运行时。首次启动需提供口令。

Windows PowerShell：

```powershell
$env:DEVKIT_PROJECT_PASSWORD='替换为独立访问口令'
$env:DEVKIT_SHARE_PROJECTS='true'
node server/start.mjs
```

Linux：

```sh
DEVKIT_PROJECT_PASSWORD='替换为独立访问口令' DEVKIT_SHARE_PROJECTS=true node server/start.mjs
```

默认监听 `0.0.0.0:8765`。首次用 `DEVKIT_SHARE_PROJECTS=true`、`DEVKIT_SHARE_NGINX=true`、`DEVKIT_SHARE_HTTP=true` 至少选择一个服务，编辑和执行另行授权；后续复用已保存设置，明确的环境变量逐项覆盖。所有变量见 [共享工作台](docs/workspace-sharing.md)；`HOST`、`PORT` 设置监听，`DEVKIT_PROJECT_DATA` 可显式指定数据目录。后续启动可复用已保存的口令哈希。HTTP 共享用于可信局域网；同一配置目录只能由一个主机进程使用。完整步骤与权限处理见 [项目中心使用和部署说明](docs/project-center.md)。

构建机使用 Node.js 24；制作 `.deb` 或独立服务 ZIP 还需 Python 3.10+。首次下载构建依赖和 Electron 运行时需要网络，已安装的离线工具使用本地资源。

npm ci

`bundle:all` 在 Windows 构建机依次制作三平台安装包，汇总 `SHA256SUMS`、`release.json` 和当前 README；独立服务 ZIP 使用单独的打包命令。仅汇总已经构建的安装包可运行：

### README 自动维护

**每次打包都会先根据当前功能生成根目录 README.md，失败时停止打包。** Windows、Linux、麒麟别名、解压版、合集（含 `--collect-only`）及独立服务 ZIP 均覆盖；直接运行打包脚本同样生效。安装包、输出目录、解压版、发行合集和独立服务 ZIP 会附带当前 README 及其链接的专题文档。

```sh
npm run docs:update   # 手动同步 README
npm run docs:check    # 只检查一致性，过期时返回失败
npm run test:docs     # 验证自动更新逻辑
```

维护来源：

- `src/tools.ts` 及其引用的工具模块：自动读取实际工具名称和功能说明，新增、删除、重命名或修改说明均同步到清单。
- `src/catalog.ts`：自动读取分类和工具顺序；工具遗漏、重复或引用失效会阻止生成。
- `package.json`、`scripts/release-integrity.mjs`、`src/workbench.ts`：自动读取版本、Electron 版本、发行文件名、打包命令和任务数量限制。
- `docs/README.template.md`：维护工作台、项目中心、部署和使用边界等说明。相关功能改变时同步修改模板及专题文档，再生成 README。

生成不依赖在线 AI 或网络；内容相同不会重复写入，也不写入构建时间。请修改上述来源，避免直接编辑会被重新生成的根目录 README。

## 验证与使用边界

```sh
npm run docs:check
npm run test:docs
npm test
npm run test:desktop
npm run test:projects
npm run test:release
npm run test:electron
npm run build
python scripts/test-deb-packaging.py
```

生成的 Java 代码可额外用 JDK 17+ 验证：`npm run test:java`，也可传入 `javac` 路径。桌面集成测试覆盖本地协议、Worker、沙箱及原生保存桥接；保存对话框的选择使用测试桩。真实安装、目标 Linux / 麒麟启动及跨电脑网络访问需在对应环境确认。

- 文本工具在独立 Worker 中执行；正则超过 3 秒、其他任务超过 10 秒会终止。通用输入上限为 2,000,000 个 UTF-16 单元，输出为 4,000,000 个；部分工具有更小限制，具体见界面说明。
- JSON 格式化保留数字原文与重复键；JSON / YAML 转换拒绝重复键等不兼容结构，转换不保留注释和排版。CSV 默认保留字符串，并对导出中的表格公式字符串转义。
- JSON 转类型按样本推断；类型转 JSON 按声明生成示例，不执行源码，也不还原真实数据。详见 [类型转换说明](docs/type-conversion.md)。
- SQL / 代码工具仅格式化或生成代码，HTTP 工具不发送请求，Cron 只预览 UTC 时间，JWT 仅解码、不验证签名。前后端工具的具体支持范围见 [开发工具说明](docs/developer-tools.md)。
- 工作区、项目导出和配置文件包含明文业务数据，应按实际内容保管；任务内容不会自动持久化，主动复制、导出或共享由用户决定。
