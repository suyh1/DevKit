# Nginx 配置与实例管理

在侧栏或顶部打开 **Nginx 配置**。该模块与项目中心平级，用于 Windows / Linux 桌面本机，需事先安装对应系统与 CPU 架构的 nginx。桌面共享与独立 Node 服务均可显式开放实例表单、主机路径填写、配置、日志和授权运行操作，参见 [局域网共享工作台](workspace-sharing.md)。

“尚未添加 Nginx 实例”只表示工作区还没有登记实例，不代表本机没有安装 nginx。可直接选择“新建配置”或“导入已有文件”；Windows/Linux都支持一份主配置关联多份附属文件。

## 从目录创建全新配置

没有现成文件时，在“添加实例”中切换到 **新建配置**，填写实例名称、选择目标系统和配置目录，可调整主文件名、附属文件名与监听端口。点击“创建文件并添加实例”后生成并自动登记：

```text
所选目录/
  nginx.conf             主配置，已 include 公共代理文件
  common_proxy.conf      附属配置，默认 /api/ 代理规则
  html/index.html        默认首页
  logs/                  日志和 PID
  temp/                  请求及代理临时目录
```

默认使用8080端口且仅监听127.0.0.1；公共代理目标为 `http://127.0.0.1:9000`。两份配置均可在字段/全文视图修改，默认目录作为实例运行目录。Windows/Linux使用相同的可移植模板，不依赖另外准备mime.types。创建不会自动启动；检测nginx程序时会保留所选配置目录，之后可检查、启动或重载。

主/附属名称须为不同的普通`.conf`文件名，禁止路径穿越、保留设备名和子目录。目标已有同名配置会阻止创建；原有首页不覆盖，所需子目录被文件或符号链接占用时提示更换目录。失败时撤销本次新建内容；新建文件若被外部修改则保留并报告，不删除外部内容。

## 登记已有配置

1. 点击“添加实例”，填写名称并选择目标系统。
2. 选择主配置文件，例如 `D:\workspace\HLD\front\nginx\nginx-win.conf`。选择文件时自动解析 include，也可手动填写路径后点击“解析附属文件”。
3. 确认运行目录（`-p prefix`）。一般使用原来启动 nginx 时的安装/运行目录；可点击“检测 nginx 并填入运行目录”读取安装信息。自动检测 PATH、常见位置或指定的程序，找不到时手动选择 `nginx.exe` / Linux `nginx`。检测按钮会覆盖运行目录，自定义过的目录需再核对。
4. 附属文件每行一个绝对路径。`common_proxy.conf`、`mime.types` 和通配符引入的文件均可编辑，循环/重复引用只列一次。扫描最多 100 个文件、递归 32 层，无法读取或缺失的引用给出提示。
5. 保存实例。只登记文件路径，不修改原文件，不启动进程。手动添加的文件只有被主配置实际 include 才会生效。

Windows 实例可维护 `nginx-win.conf` 与 `common_proxy.conf`，Linux 实例可只登记 `nginx-linux.conf`。可以在同一台电脑编辑两类配置，运行操作只对匹配系统启用。“跟随本机”适合可直接跨系统使用的配置。

局域网网页仅是主机工作台的远程操作界面：所有输入路径（主文件、附属文件、运行目录、程序）都指运行 DevKit 的主机；新建/读取/保存和启动、停止、重载都由该主机执行。编辑访客可直接登记和维护实例，浏览器不使用客户端文件选择器。

## 路径解析

| 内容 | 相对路径基准 |
| --- | --- |
| 主配置 `-c` | 始终传入已登记的绝对路径 |
| `include common_proxy.conf`（含嵌套 include） | 主配置文件所在目录 |
| `pid`、日志、静态目录等 prefix 路径 | 实例的运行目录 `-p` |
| 未写 `pid` | nginx 编译时 `--pid-path`，无该参数则 `logs/nginx.pid`；相对路径再基于 prefix |

Windows 配置路径推荐正斜杠，如 `D:/workspace/nginx/logs/error.log`。含空格的参数使用引号，如 `root "D:/web sites/dist";`。实例路径可使用系统常规写法。所有命令参数独立传递，不经过 cmd 或 shell。

## 字段与全文编辑

默认按 `http`、`events`、`server`、`location`、`stream`、`upstream` 及自定义块的原文层级显示字段，可搜索指令、端口、域名和路径。常用字段提供工作进程、连接数、PID、日志、include、监听地址、域名、静态目录、首页/SPA 回退、代理目标/请求头、上传大小、超时、证书及重定向说明；其他指令同样显示原参数。

### 字段填写提示

实例表单中每个输入项旁的“？”提供用途、填写格式与影响；鼠标悬停、点击或键盘聚焦问号时弹出，点击外部或按Esc关闭。说明不常驻字段下方。主文件导入不要求重填监听端口或代理目标。新建表单的端口仅生成第一个示例服务，`http://127.0.0.1:9000` 仅是示例后端，可在创建后按实际服务调整。同一实例可配置多个 `server` 和多条 `listen`，公共文件可包含多条不同的 `location` / `proxy_pass`。

配置字段的“？”提供中文用途和示例参数；PID、日志、静态目录提示当前运行目录，include和证书路径提示当前主配置所在目录，均可填写绝对路径。示例只演示格式，不会自动替换原值。字段仅填写参数，不加指令名、分号或注释；全文和新增指令框则填写完整语法。未知/自定义模块保留通用语法提示，不推测模块含义。HTTP站点、upstream中的后端节点与stream TCP/UDP服务按层级给出不同说明。

附属文件编辑区“填写规则”的问号解释实际引用关系及共享影响：修改公共规则会影响所有include它的服务。普通HTTP前缀location中的proxy_pass说明末尾`/`对路径替换的影响；变量、正则等特殊情况仍需核对[官方代理文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)。

仅输入字段保留问号，操作按钮和配置块标题不再额外添加提示，也不显示操作说明汇总。推荐 **保存 → 检查配置 → 启动或重载**；检查不代表后端接口可访问，重载后还需实际访问与查看错误日志。输入项通过aria-describedby关联提示。浮层沿用深浅主题，并限制在视口内；窄屏可点击打开。Esc仅关闭提示，不关闭下层表单或丢弃草稿。

保留重复指令、变量、正则、注释及未知模块。字段参数按 Enter 或离开输入框提交到草稿；无效参数显示错误，Esc 恢复。每个配置块可添加指令/子块或删除整个块，新增模板需按模块和层级调整。

“全文编辑”提供完整文档、查找、撤销与行号。主文件与附属文件均使用 Nginx 语法高亮，区分指令/块名称、字符串与路径、`$host` / `${host}` 等变量、数字/容量/时间、开关和注释；颜色跟随深浅主题，输入时即时更新，无需联网。未知模块的指令也按位置着色，着色不改写配置。

结构错误时字段视图提示行号，修复全文后恢复。语法高亮只辅助阅读，不判断指令是否有效；结构解析只检查词法、括号和分号，模块与资源权限以 `nginx -t` 为准。嵌入 Lua、Perl 等第三方非 Nginx 语法的块暂不保证可解析或正确着色，结构解析不通过时阻止保存。

配置写入采用同步临时文件和原子替换；Windows遇到EPERM/EACCES/EBUSY等短暂占用时有上限重试，持续失败保留原文件并报告。

多个文件分别保留草稿与修改标记，“保存文件”保存所有修改文件。切换项目中心或普通工具保留草稿；切换实例、重新读取、刷新会提示放弃，关闭应用也有未保存保护。Nginx 配置不包含在文本任务的“保存工作区”快照中。

实例表单只有实际改动才启用保护，打开未填写的表单或将内容改回原值可直接取消。表单关闭、应用退出和重新加载统一使用当前主题的确认弹窗，默认聚焦“继续编辑”，Esc等同取消确认；不再同时显示系统提示和表单底部警告。取消应用退出会保留当前草稿和管理器连接，确认退出后才释放配置锁。表单仅中间区域滚动，保存/取消按钮保持可见。

## 保存、备份与恢复

- 仅支持 UTF-8 文本（最多 2,000,000 字符），保留已有 BOM、CRLF/LF 和未编辑片段；UTF-16/二进制需先转换编码。
- Nginx 本身可能拒绝 UTF-8 BOM；编辑栏在发现 BOM 时提供“移除 UTF-8 BOM”，点击后进入草稿，保存前仍备份原文件。
- 写入前检查所有修改文件的内容哈希，发现外部修改则整批拒绝。先复制草稿到外部位置，再重新读取合并。
- 每次保存前在 `configs/nginx/backups/<时间戳-编号>/` 保存清单和原文。备份持续留存，可手动归档。备份可能含内部地址或密钥等敏感内容，请按原配置权限保管。
- 临时文件在原文件同目录，写完后替换；Linux 保留权限位，不改变所有者。部分写入失败时尝试回滚，若回滚时再次被外部修改则保留外部改动并报告。跨文件无法提供操作系统级事务，请避免其他程序同时写文件。
- “备份 → 载入草稿”后核对再保存，该保存也备份当前磁盘内容。备份中已取消登记的文件需先重新登记。
- 确认运行或 PID 进程身份存疑时，停止实例后再修改 `pid` / `include`。主文件、程序、运行目录及目标系统在运行期间同样不可调整。

**保存不会自动重载**。先保存、检查，再启动或重载。检查失败时修正后重新保存。

## 运行控制

沿用指定主文件的命令，并明确运行目录：

```text
nginx -p <运行目录/> -c <主文件绝对路径> -t
nginx -p <运行目录/> -c <主文件绝对路径>
nginx -p <运行目录/> -c <主文件绝对路径> -s reload
nginx -p <运行目录/> -c <主文件绝对路径> -s quit
```

Windows 使用独立后台进程，等价于示例中的 `start nginx -c ...`，不显示 cmd 窗口；Linux 使用 nginx 默认后台方式。命令区显示检查与信号命令的参数和原始输出；后台启动结果通过 PID 与进程身份确认。启动时的端口占用等错误可能只写入配置中的 error_log，无法确认启动时请检查该日志。不自动提权或安装系统服务。

### 自动准备运行目录

“检查配置”、直接“启动”和“重载”都会先扫描主文件实际引用的include（含嵌套及通配符），递归创建缺少的运行目录。包括pid/error_log/access_log/lock_file的父目录、client_body/proxy/fastcgi/uwsgi/scgi临时目录、各类cache_path和working_directory；固定路径的store也准备父目录。相对路径基于实例运行目录，绝对路径保留原位置。仅登记但未被include的附属文件不参与目录准备。

自定义运行目录本身也可尚不存在，保存实例只登记路径，首次检查/启动/重载时再递归补齐；若该路径已被普通文件占用则提示更换目录。

未显式配置的默认日志/临时目录以当前nginx的`-V`编译选项及真实`-t`缺目录结果按需补齐，并重新检查，避免创建未使用的系统目录。实际新建路径列在执行详情中；已有目录、日志及PID文件不会被工具覆盖或清空，不改变配置文本，也不更改目录权限/所有者。后续由nginx按其原规则打开日志及写入PID。

含变量的目录无法提前确定，保留提示；off、stderr、syslog及内存日志等特殊目标不会当成目录。配置、证书、密钥和前端文件属于输入资源，不生成空文件代替，也不创建空站点来掩盖路径错误。缺少这些资源、目录无写入权限或同名路径被文件占用时，明确报告路径和原因并停止启动/重载。目录准备失败时保留已成功创建的空目录，便于修正权限后重试；不删除已有内容。“停止”、状态刷新和编辑/保存不触发目录创建。

### 固定操作区

实例信息、检查/启停/重载、保存/备份和执行反馈在配置正文滚动时吸顶，位于工作台导航下方。吸顶后平滑收起长路径和辅助说明，保留实例名、状态及主要操作；“展开详情”可随时查看完整运行信息。执行反馈收为摘要，可点击展开，新命令结果会自动展开且高度有界，避免遮住整个编辑区。窄屏操作分组可横向滚动，键盘焦点会带出对应按钮；系统设置减少动态效果时关闭过渡。

启动/重载前执行 `-t`，失败则不继续。停止发送 `quit`，长连接可能需要等待后刷新确认。重载成功表示已发信号且主进程仍运行，最终是否接受新配置应结合错误日志与实际访问核对。配置检查可能创建空 PID 文件，此时视为已停止。

状态每 15 秒刷新，也可手动刷新：

| 状态 | 含义 |
| --- | --- |
| 运行中 | PID 存活、程序路径及命令中的主文件匹配，允许重载/停止 |
| 已停止 | 未发现 PID、PID 为空或对应进程已退出；启动仍需通过配置检查 |
| 待确认 | 检测/读取/权限失败，PID 无效或属于另一配置；拒绝进程操作并显示原因 |
| 其他系统 | 可编辑文件，不能在本机执行该系统配置 |

并行实例使用不同 PID 文件、日志/临时目录和监听端口。共用附属文件可行，修改后需分别检查各实例。共享 PID 指向另一主文件时不会误停它。没有明确 `-c` 的已有进程不能可靠匹配，请先用原管理方式停止，再由工具启动；不要删除运行中的 PID 文件。

退出 DevKit 不会停止 nginx。注册表在 `configs/nginx/instances.json`；迁移 configs 会携带注册表和备份，不会复制外部 conf 或 nginx 程序，需调整对应路径。

## 日志查看与变更审阅

选择实例后点击“查看日志”，从主配置及其实际 include 识别显式配置的 access_log/error_log 文件。相对日志路径基于实例运行目录；off、stderr、syslog、内存日志和带变量的路径不当作文件读取，未显式声明的编译默认日志不猜测路径。列表不是任意文件浏览器，后台每次读取前重新核对当前生效配置。

可按关键词、错误级别和末尾 100/300/1,000/2,000 行筛选；每次最多读取末尾 1MB，筛选仅作用于此窗口。文件日志按 UTF-8 展示；非 UTF-8 字节可能显示替代符，不修改日志编码或原文件。“跟随日志”每两秒读取一次，切换模块或收起日志后停止读取；“暂停跟随”保留当前文本。轮转/截断后重新读取当前路径并提示。可刷新或导出当前筛选片段，缺失文件/权限错误直接展示，不创建、清空或轮转日志。

“变更与引用预览”将当前草稿与重新读取的磁盘内容比较，按文件展示新增/删除行；若磁盘版本与编辑基线不同，会标注外部修改，保存仍受原有版本检查保护。“备份 → 对比当前”比较备份与当前磁盘；载入备份草稿和保存仍为独立动作。大文件或复杂差异超出快速预览范围时提示导出查看。

引用面板扫描所有已登记实例的实际 include，显示共享文件、引用源文件/行号及所在 server/location 上下文，可跳转到对应文件。动态 include、缺失文件、循环及扫描上限会明确提示，未登记实例不在影响范围内；该面板依据当前磁盘关系，不模拟草稿里尚未保存的新引用。每实例最多扫描 100 个文件、32 层、1,000 次引用访问及 10,000,000 字符，重复引用复用已读取内容。导出的审阅报告包含前后配置原文，需按实际内容保管。

## 删除实例记录

实例卡片下方的“删除”和选中实例顶部的“删除实例”均可发起删除，有未保存修改时也可使用。确认框显示实例名称和删除范围；删除当前实例会提醒一并放弃其草稿，取消则保持全部输入。删除未选中的实例不会丢弃当前正在编辑的草稿。

确认后仅移除DevKit实例记录，原配置文件、共用附属文件和备份全部保留。已经运行的nginx继续运行，若希望停止它，应取消删除并先执行停止。删除当前项后自动选择相邻实例，最后一项删除后回到新建/导入空状态。列表和顶部操作仅在有请求进行时暂时禁用。
