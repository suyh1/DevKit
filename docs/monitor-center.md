# 监控中心

监控中心是与项目中心、HTTP 调试、Nginx、JAR 管理平级的共享栏目。检测由运行 DevKit 的主机执行，网页每 5 秒读取状态；浏览器的 `localhost` 不作为目标主机。

## 添加与关联

点击“添加监控”，填写名称，选择自定义 HTTP(S) / TCP 地址，或关联项目入口、JAR。新监控默认暂停，勾选“保存后启用定时检测”才开始自动执行。

- HTTP 使用 GET，仅读取响应头，精确匹配预期状态码（默认200）。HTTPS校验证书，拒绝URL内嵌用户名/密码，最多5次重定向，全程共用超时。认证页面的401/403不代表进程已停止。
- TCP填写不带协议的主机名/IP和端口，只检查能否建立连接，不验证协议或业务内容。
- 关联项目固定到选定档案和项目标识，检测时重新解析该档案的变量与入口，不随访问者切换档案。项目删除、停用或缺变量均显示检测失败。
- 关联JAR使用该应用当前HTTP/TCP健康检查的目标和预期状态；检测间隔、超时、失败确认次数由监控配置决定。JAR未设置健康检查时显示明确失败；不启动、停止或重启应用，不将PID存活视作健康。
- 共享选择器只列出同时开放的项目/JAR服务；不会返回JAR环境变量或启动参数。关闭项目/JAR共享不会暂停已经由主机配置的关联监控。

检测间隔10–86,400秒，超时1–60秒，连续失败确认1–10次。每次完成后再计算下一次检测，不堆积遗漏任务；全主机最多3项同时检测，同一项手动与定时检测合并。

## 状态、趋势与故障

首轮前或检测记录超过 `max(3 × 检测间隔, 超时 + 10秒)` 时显示“待检测 / 已过期”。一次失败显示待确认，达到连续失败阈值时创建一个故障事件；持续失败不会重复创建，下一次成功关闭该事件。

状态卡展示最近24小时已保留样本的成功比例和平均耗时，心跳条与曲线展示最近60次检测；详情可查看最近30次检测和故障/恢复记录。可用率按检测样本计算，不是按持续时间计算的SLA；没有样本时显示横线。故障在页面中持久记录，第一版没有邮件、Webhook或第三方消息通知。

最多100项监控，每项保留最近1,440个且不超过7天的样本和最近100个故障事件。高频或大量手动检测可能使保留时间少于24小时，页面显示实际样本数。修改监控配置会开始新检测序列，关闭旧未恢复事件并注明配置变更，旧故障记录保留；删除监控会删除对应全部历史，需确认。

## 暂停与维护

启停按钮仅控制定时检测，不控制目标应用。暂停期间不产生样本，故障记录仍保留。编辑表单可填写一个维护开始/结束时间，按当前浏览器本地时间输入，保存为带时区的ISO时间；维护期间不检测，不计为成功，不自动关闭已有故障。到期后自动恢复调度。维护窗口与其他配置一起保存，编辑权限规则相同。

关闭页面、切换栏目或进入桌面托盘后，主机继续检测；退出DevKit或独立Node服务后停止。重新启动读取保存的监控并恢复调度，不补造离线样本。独立服务适合常驻主机，服务本身的系统自启由部署者配置。

## 共享与权限

全局“局域网共享”中单独选择“监控中心”。旧配置升级时默认关闭该服务，也不会自动授予编辑或运行权限。

| 权限 | 能力 |
| --- | --- |
| 只读 | 查看配置、状态、历史与故障记录 |
| 编辑 | 新建、修改和删除暂停的监控，设置关联与维护窗口 |
| 运行 | 启用、暂停、立即检测；修改/删除运行中的监控还需编辑权限 |

保存检查配置版本，多人并发编辑时拒绝旧版本保存并保留当前草稿。点击页面“刷新”可读取主机最新状态；发生冲突后重新打开编辑表单，核对后再保存。

共享工作台须口令登录，本版没有匿名公开状态页。监控地址及故障信息对获准访问监控服务的用户可见，不应在URL查询参数内保存秘密。

## 存储与独立服务

配置、样本与事件保存在 `configs/monitor/monitors.json`，采用目录锁、串行保存、原子替换，保存失败保留上一份内存/磁盘状态并在页面提示。错误存储不会被空数据覆盖。配置版本只在用户修改配置时递增，后台样本不会导致编辑冲突。迁移时关闭应用/服务后复制整个 `configs`；项目中心JSON导出不包含监控。

独立服务新增环境变量：

| 变量 | 含义 |
| --- | --- |
| `DEVKIT_SHARE_MONITOR=true` | 开放监控中心查看 |
| `DEVKIT_MONITOR_EDIT=true` | 授予监控配置编辑 |
| `DEVKIT_MONITOR_CONTROL=true` | 授予监控运行权限 |

布尔值只接受 `true` / `false`，未指定时复用已保存设置。启动共享服务不自动启用任何监控；监控是否运行由各项配置的启用状态决定。即使未向访客开放监控服务，主机上已经启用的监控仍会执行。完整部署方式见[共享工作台](workspace-sharing.md)。

## 设计参考与验证

对比[Uptime Kuma](https://github.com/louislam/uptime-kuma)（MIT、约93.2k stars，Node/Vue常驻服务）与[Upptime](https://github.com/upptime/upptime)（MIT、约17.2k，依赖GitHub Actions和Git记录）。前者更符合内网主机调度，后者的GitHub依赖不适合离线部署。本项目借鉴探测、故障确认和状态展示流程，复用已有Node基础，不复制第三方代码、不增加运行依赖。

主要边界是重定向环、证书失败、慢响应、配置与检测同时更新、多个访客重复提交、历史容量和主机停机期间的未知状态，分别通过截止时间、并发上限、结果代次和有界记录处理。测试：`npm run test:monitor`；真实桌面/共享只读界面：构建后 `node scripts/smoke-desktop.mjs --monitor-only`。
